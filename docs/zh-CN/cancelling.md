# 暂停与停止下载

[English](../cancelling.md) | [简体中文](cancelling.md)

下载界面控制栏中的**暂停（Pause）**按钮会将原生传输原地挂起。下载/录制界面保持不变，工作线程在分段间隙等待，同一按钮切换为**继续（Resume）**以便接着运行当前任务。暂停不是取消：已验证的分段仍保留在 `tmp` 中，任务也处于运行态。

真正停止下载依然使用 `^b`。底部按键栏会明确标出 `^b` 当前对应的行为，不需要猜测：

| 状态 | 顶部控制按钮 | `^b` 提示 |
|---|---|---|
| 无运行中任务 | 完成 / 继续已结束条目 | `back`（返回） |
| 下载中 | 暂停（Pause） | `stop everything`（停止全部） |
| 已暂停 | 继续（Resume） | `stop everything`（停止全部） |
| 正在停止 | 正在停止（Stopping） | `stopping...`（正在停止…） |

暂停会在下一个分段或直播刷新点生效。返回（Back）、首次退出（Quit）以及跳过仍会执行取消。早期的 Stop 控件会立即取消，现已由 Pause 取代。

## 停止或完成后的返回行为

返回（Back）会回到发起当前步骤的紧邻上一级页面，而不是直接跳回服务主页。无论任务成功还是失败，父级目标一致：停止或关闭结果页后恢复所属的选择器或输入页。关闭弹窗时不会连带离开底层页面。只有当服务主页确实是上一级页面时，返回才会回到服务主页。
关于嵌套搜索/季/集流程、自定义服务委托以及详细的导航契约，请参阅 [navigation.md](navigation.md)。

## 批量下载中的失败标题

manifest、许可证或已选轨道的准备阶段若发生失败，该标题会直接标记为失败并保留队列行以供重试，其余标题继续执行；许可证获取失败（包括 Widevine/PlayReady 返回空密钥响应）不会遗留一个隐藏的选轨询问卡住流程。未加密媒体与普通 HLS AES-128 不需要内容密钥对。

最后一个标题结束后，即使该标题失败，队列也会退出繁忙状态。此时按返回（Back）会正常返回，不会试图去停止一个并不存在的传输。在准备阶段取消同样会关闭待响应的下载/选轨询问，并停止批次中尚未开始的剩余标题；但服务级提示与登录提示不会被下载取消动作关闭。正在进行中的同步服务请求可能仍需等待其配置的网络超时后返回，但只要当前没有活跃传输，界面就不会误报正在等待媒体分段。

## 查看批量任务中的标题详情

点击下载队列中的任意标题行即可打开其详情弹窗，包括已完成、运行中、失败和排队中的标题。打开弹窗不会暂停传输、不会修改选轨，也不会额外请求 manifest、许可证或媒体分段。可使用弹窗内紧凑的上一项/下一项按钮或左右方向键切换查看相邻标题。按 `Esc`、`Ctrl+B` 或点击关闭图标仅关闭弹窗本身，不会停止下载。

已完成的行会保留最近一次尝试中实际报告的输出路径、已确认的所选轨道、各轨道 KID、可用密钥、元数据统计及耗时信息。总耗时包含准备阶段与手动选轨时间；下载与处理耗时覆盖原生传输、解密与混流全过程（包含暂停时长）。失败或取消的行会保留截至中断前已收集的信息，其显式**重试（Retry）**按钮仅在没有活跃任务时启用。直接点击队列行本身不再触发重试。

普通的未开始标题会显示**排队中（Queued）**：UniDL 不会为了填充弹窗详情而提前对其发起授权。若选片阶段已有标题名则显示该名称，否则使用带编号的占位名。原生批量导入的文件在开始下载前即可展示保存的标题、manifest 引用、导出的轨道列表、密钥和元数据。导出的轨道列表会与本次已确认的选轨分开标注；已保存的信息并不保证带过期时间的 URL 或密钥仍然有效。待开始行绝不计为已启动任务，也不会进入重试队列。

这些详情只是轻量的内存会话记录，并非另存一份导出文件或调试日志，不会保留已解析的分段列表、许可证载荷、Cookie 或账号令牌。内容密钥会刻意保持可见：请将它们与签名 manifest 链接视为敏感信息，分享截图前务必先打码脱敏。开始新的批量任务时，上一批的详情历史会被清空。

## 批量标题之间的延迟

全局设置**下载行为 → 标题之间的延迟（Download behavior → Delay between titles）**用于在自动多标题点播批量任务中插入调度延迟，默认关闭。输入 `30` 表示固定等待 30 秒，输入 `20-40` 表示在该区间内随机等待，输入 `off` 关闭。第一个标题立即开始，等待发生在下一个标题进入服务准备、manifest 处理或获取许可证之前。同一标题内的各条轨道以及直播录制分段绝不会被延迟，重试也不会额外叠加第二次标题等待。

显示延迟倒计时期间，**暂停（Pause）**会冻结倒计时，**继续（Resume）**会恢复计时；**返回（Back）**、**Escape** 或 **退出（Quit）**会取消剩余批次。该等待是可中断的，停止时不会遗留休眠中的工作线程。

## 工作原理

原生交付调用是同步的，因此取消信号通过显式的 `CancellationToken` 传递，而不是靠劫持终端输出。后端在传输工作线程和直播刷新循环中持续检查该令牌，取消待执行工作并清理临时状态。

取消操作同样能直接释放已暂停的传输，无需先点**继续（Resume）**。即使处于暂停状态，按返回（Back）或退出（Quit）也会取消剩余批次。停止信号会立即发出，而套接字与子进程清理在 TUI 主线程之外执行，保证界面导航与工作回调持续响应。原生 HTTP 套接字读取会在关闭缓冲响应之前被主动中断。下载任务的持有方会等待清理完毕后再返回，不会在后台遗留孤立的下载器进程或资源清理线程。

公开返回结果为 `DeliveryStatus.CANCELLED`，退出码为 `130`。因为是用户主动要求停止，它不会被当作下载失败上报。

`Ctrl+C` 与返回/停止走同一条路径：UniDL 中止当前活跃会话、关闭原生下载器的套接字和子进程，然后通知 Textual 退出事件循环。终端状态会正常恢复且静默处理中断，因此主动停止不会打出 Python `KeyboardInterrupt` 堆栈。清理过程中若再次收到中断信号，会被忽略而不会递归触发新一轮关停。

这套机制依赖两项已验证的前提：

- **渲染权归属 UI。** 结构化的 `TrackProgressEvent` 事件由交付界面统一绘制，没有任何进度线程直接往终端写输出。
- **独立命令保持有序行为。** `unidl download` 保持自身独立的终端行为，而嵌入式 TUI 通过 Core 契约接收完全一致的取消语义与状态回传。

### 实际限制

取消信号会在下一条进度更新时被察觉，而不是零延迟瞬时中断，实际通常在不到一秒内响应。卡死在套接字上的下载会由内置运行时强制关闭其传输连接来释放；对不配合退出的工作线程，会给予有限的清理时间窗口后再返回。

在开启 `resume_parts`（默认开启）的情况下，取消后已完成的分段文件会继续保留在 `paths.temp` 下。对于直链单文件下载，只要源站确认支持 HTTP Range，已下载的前缀临时文件也会保留，下次运行时直接从该字节偏移续传；若源站不支持 Range，UniDL 会丢弃该前缀并安全地从零重新下载，避免产出重复拼接的媒体文件。

## 恢复已完成轨道与处理阶段

开启 `resume_parts` 后，点播重试所保留的不仅是未完成的分段。每条轨道在完成下载、解密、重封装、音频处理和字幕准备后，都会发布一个经校验的阶段检查点（checkpoint）。失败的阶段无法覆盖前一个有效检查点。例如，音频已准备就绪但视频下载到一半失败，重试时会直接复用已准备好的音频，并接着下载视频剩余分段；若混流失败，则可直接复用所有已准备完成的轨道，无需重新下载或解密。

检查点存放在任务的 `paths.temp` 缓存下，与每次运行独立且用后即弃的 `.work` 工作目录隔离。检查点并非最终成品文件。检查点记录采用原子替换写入，并通过轨道标识、处理选项、文件大小、修改时间及有界内容采样进行校验，绝不会仅因文件名一致就轻信一个缺失、被改动或不兼容的文件。共用同一缓存目录的多个任务在最终提交阶段会串行执行，防止某次调用误删另一任务的活跃输入文件。

三个相关选项各司其职：

- `resume_parts`：失败或取消后复用已验证分段和有效的阶段检查点。关闭后会跳过这些检查点从头开始。
- `keep_temp`：下载成功后仍保留缓存以供排查或复用；调试模式也会自动启用保留。失败恢复并不依赖此项。
- `keep_failed_intermediates`：失败时额外保留失败的工作目录（含不完整的输出文件）以便调试。关闭后会清理这些失败残余，但不会删除有效的续传检查点。

正常清理流程会在耐久的轨道检查点生成后释放冗余的分段文件；剩余检查点则只在最终成品成功提交后才会被清理（并服从既有的成功后保留设置）。失败的混流输出属于可丢弃残余，而有效的源轨道不会被误删。在支持硬链接的文件系统上，检查点媒体文件会直接共享已有文件数据，避免重复拷贝大体积轨道；在其他文件系统上则使用有界内存流式复制。直播录制仍保持其独立的可见文件、返回（Back）收尾提交与退出（Quit）保留行为。

## 对批量任务的影响

取消其中任意一个标题会一并取消整个批次的剩余部分。你发出的是停止指令，而不是跳过这一集继续下后面九集。

剩余的每一个标题仍会在队列中生成一行并标记为 `⊘ cancelled`，确保队列完整交代整批任务的状态，而不是在中途戛然而止。

## 取消不等于失败

| | 颜色 | 标题栏 | 是否停留页面 |
|---|---|---|---|
| 失败（failed） | 红色 | `finished with errors` | 是 |
| 取消（cancelled） | 暗淡色 | `stopped` | 否 |

取消是你主动做出的选择，因此不会标红示警、不计入失败数量，也不会把你拦在当前页面。失败则恰好相反，上述三项都会触发。

当一个批次中同时存在失败与取消时，标题栏优先显示失败：因为那是你此前尚未预料到的情况。

## 验证方式

运行离线测试套件，并配合刻意放慢速率的本地测试夹具验证取消能够及时中止传输：

```bash
python -m pytest -q
```
