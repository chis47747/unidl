# 界面语言与本地化

[English](../i18n.md) | [简体中文](i18n.md)

UniDL 的界面语言是一项全局应用设置，与各服务的 API 语言区域以及音视频/字幕轨道语言完全解耦。服务目录和媒体元数据保持 Unicode 安全且不做翻译，页头标题横幅也会直接渲染 CJK 和 RTL 服务名而不对其进行翻译。

## 支持的语言区域

UniDL 在 `src/unidl/locales/*.json` 中内置了 12 份语言包：

| 语言代码 | 语言 | 说明 |
|----------|------|------|
| `en` | 英语（English） | 源语言与默认回退语言包（美式英语）。 |
| `zh-Hans` | 简体中文 | 简体中文 |
| `zh-Hant` | 繁体中文 | 繁體中文 |
| `es` | 西班牙语 | Español |
| `fr` | 法语 | Français |
| `pt` | 葡萄牙语 | Português |
| `it` | 意大利语 | Italiano |
| `ja` | 日语 | 日本語 |
| `ko` | 韩语 | 한국어 |
| `ru` | 俄语 | Русский |
| `de` | 德语 | 列表中显示为 **Deutsch**；`de-DE`、`de-AT`、`de-CH`、`de-LI` 和 `de-LU` 均映射到此项。 |
| `ar` | 阿拉伯语 | العربية —— JSON 中保存纯逻辑顺序 Unicode 文本，渲染时按从右到左及镜像布局规则显示。 |

可在**设置 → 界面与诊断 → 界面语言**中切换语言。默认的 `system`（跟随系统）选项按顺序检查环境变量 `LC_ALL`、`LC_MESSAGES` 和 `LANG`，未命中则回退到 `en`。切换语言会原地重绘当前活动页面和浮层，无需重启会话，也不会使登录状态失效。

## 翻译边界

只有 UniDL 自身拥有的界面文案会被翻译：

- 顶栏与底部快捷键栏标签（`Back`、`Quit`、`Search`、`Settings`）；
- 选择器标题、提示文案、校验报错与交付状态；
- 全局设置项标签/帮助及管理页面（下载行为、服务、DRM 与密钥库、文件与命名、代理与 VPN、JustWatch、定时下载、界面与诊断）；
- 命令面板条目、快捷键速查、搜索与密钥库弹窗，以及原生下载器的进度/状态文本；
- UniDL 自身生成的诊断信息与通知消息。

以下数据始终保持原始逻辑 Unicode 顺序，绝不翻译：

- 服务名称、片名、分集名以及账号标签；
- URL、文件路径、文件名、KID、密钥、编码格式及 DRM 标识符；
- 服务自身返回的 API 错误和元数据（除非服务显式提供了显示标签）；
- 用户输入，以及写入命令文件、导出文件或密钥库中的任何内容。

界面语言绝不会改变任何服务的 API `locale` 或轨道语言选择规则。

## 实现机制

UniDL 在 `src/unidl/core/i18n.py` 中维护包内独立的文案目录，而不使用 Python 进程全局的 `gettext` 区域设置，确保多会话并发时不会污染服务客户端或 shell 的本地化环境：

- `supported_locales()` 暴露全部 12 个稳定的语言区域代码。
- `detect_locale()` 依次从 `LC_ALL`、`LC_MESSAGES` 和 `LANG` 解析 `system` 设置。
- `tr(message_id, **values)` 按描述性的点分键名（如 `chrome.back`、`schedule.tab.jobs`）查找文案并填充命名占位符；若某个键缺失，自动回退至 `en.json`。
- 所有语言包都是从 `src/unidl/locales/*.json` 加载的静态包内数据，绝不通过网络拉取。
- 源字符串始终保持逻辑 Unicode 顺序（包括 `ar.json`，其中不得包含阿拉伯文表现形式码位 `U+FB50–U+FDFF` / `U+FE70–U+FEFF`）。在 TUI 渲染边界，由 `tui/bidi.py` 统一执行一次 BiDi 排序、阿拉伯文字形塑形和 Rich 标记转义。布局计算与文本截断均基于真实终端单元格宽度，而非 `len()` 字符数。

## 新增或更新翻译

每份语言文件都必须与 `en.json` 保持严格的键一致性：

- 全部 12 份文件均须可无错解析为 UTF-8 JSON，且拥有完全一致的键集合；
- 命名占位符（`{count}`、`{name}` 等）必须与 `en.json` 一一对应；
- 包含方括号的译文在 Rich 标记环境下必须安全转义；
- CJK 与 RTL 布局在低至 `80×24` 的终端尺寸下仍须排版整齐；
- 更改 `interface_locale` 后，服务 API 请求、输出文件名、导出文件以及密钥库记录必须保持逐字节完全一致。
