# 第三方导出文件

[English](../third-party-exports.md) | [简体中文](third-party-exports.md)

UniDL 刻意将导出文件分为两条相互独立的导入路径：

* **UniDL 原生导出文件**（`kind: unidl-export`）：由 UniDL 自带的版本化解析器读取。如果本机已安装来源服务，原生导入可保留该服务的交付钩子。
* **第三方导出文件**：由适配器转换为核心层（Core）的中立播放模型，且一律交由通用下载器完成交付。适配器支持共享的 `kind: mediaexport` v1 格式、当前 Unshackle v2 文件，以及下文所述的旧版轨道和剧集结构。该模块刻意命名为 `third_party_exports.py`，以便后续接入其他下载器格式而不削弱原生读取器的约束。

## 安全与归属边界

第三方导出文件只是静态数据，而非服务会话。其中的服务标签仅保留用于命名和展示。即便文件中带有提供方/服务标识，导入它也**不会**：

* 实例化或查询该服务的代码；
* 读取该服务的 Cookie、令牌、账号或外部工具（Helper）状态；
* 调用该服务的许可证接口，或要求 UniDL 重新为该标题申请许可证。

导出的 `KID:key` 密钥对会直接传给原生交付核心。如果加密轨道缺少导出的密钥，任务会明确报错，而不会回退去发起服务许可证请求。无加密媒体、播放列表 AES-128 及其他无需许可证的状态则照常走非许可证路径。

导出文件中的 `region` 仅为提示性元数据，会显示在导入说明中，绝不会静默转换为代理配置。如果已签名的 manifest 仍要求来源地区网络环境，请在 UniDL 设置中显式选择代理。

## Manifest 处理

共享 `mediaexport` 格式中已定型的字段均可在不加载服务代码的前提下直接导入：标题元数据、主 manifest 与附加 manifest（按完整 URL 识别）、非敏感 manifest 请求头、DRM/PSSH 提示、KID:key 密钥对、章节，以及带 URL 的外挂轨道。`Cookie` 和 `Authorization` 请求头会被丢弃。即便共享导出文件的服务标签恰好与已安装的某个服务同名，也仍会停留在通用导入上下文中。

HLS AES URI-key 记录与冻结的 `segments[]` 交付模式目前暂未启用。它们的 IV、初始化分段及逐分段语义在共享格式中仍在最终定稿阶段。UniDL 不会将这些记录静默当作普通服务 manifest 处理，也不会为其重新申请许可证；此类标题需以当前受支持的格式重新导出。

适配器会保留导出端已经解析好的媒体源。除当前的 Unshackle v2 文件外，还兼容常见旧版导出结构：

* 早期电影及多 manifest 导出使用的扁平 `title -> track label -> track` 映射；
* `series -> seasons -> episodes -> tracks` 剧集目录结构。每一集会作为独立标题导入，保留季数、集数以及导出的媒体 URL。

剧集目录中至少有一集的轨道树包含有效 URL。仅含元数据的目录会被直接判定为不可下载并拒绝，而不会静默生成空任务。旧版轨道标签仅用于补全缺失字段：显式声明的 `type`、编码、语言和 URL 始终优先。特别地，如果某条旧版记录标注了 `descriptor: DASH` 但实际指向 `.mp4` 文件，UniDL 会按直链 URL 处理，不会将其交给 DASH 解析器。

* **HLS**：在类型化 JSON manifest 中使用各导出轨道的媒体播放列表（media playlist）URL。选轨界面先展示导出方提供的元数据，推迟到选中具体轨道后才去读取对应的子播放列表，因此即便导出文件包含数十条字幕播放列表也能快速打开。随后下载水合（hydration）阶段只拉取已选中的播放列表。此优化仅作用于私有的第三方导出标记；普通服务的 JSON manifest 仍保持即时解析行为。
* **DASH 与 ISM**：直接使用导出的 manifest URL。如果导出文件包含额外的已授权 manifest URL（例如独立编码/档位的 MPD），UniDL 会通过惰性的通用导入上下文解析并合并这些 URL，全程不涉及任何服务 API 或许可证调用。
* **直链 URL 轨道**（含外挂字幕）：使用同一套类型化 JSON 源表示，不会被误判为服务 manifest。

Manifest URL 和请求头中可能携带短期有效的授权信息。请像保管密码一样妥善保护第三方导出文件：切勿公开或提交到代码仓库，签名源过期后重新导出即可。

## 密钥与 DRM

Unshackle 中按轨道存储的 `keys` 映射会被统一规范化为小写 32 字符的 KID 以及 128 位十六进制内容密钥。若同一 KID 出现互相冲突的不同键值，导入会直接拒绝，而不会静默任选其一。Widevine、PlayReady 和 ClearKeyCENC 的 DRM 标签会作为核心层提示保留，但提示本身不会授权发起新的许可证交换。若存在 PlayReady PSSH/WRM 数据也会一并保留，方便通用下载器在使用导出密钥的同时准确识别加密表示（representation）。

## 导入不会改变的行为

导入后依然遵循 UniDL 常规的输出轨道选择和下载器设置。因此，只要导出文件中包含对应轨道的 KID:key，你就可以从包含多档码率的导出文件中按其他画质下载。轨道选择与导出方使用的 API 档位以及许可证选轨相互独立。
