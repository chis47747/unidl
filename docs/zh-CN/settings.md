# 设置

[English](../settings.md) | [简体中文](settings.md)

UniDL 的设置刻意划分为三个独立层级。在任意界面点击“设置”或按 `ctrl+s` 即可编辑；当焦点不在文本输入框中时，直接按 `s` 也能快速打开。在设置界面或管理器分组中，按 `m` 可筛选出仅显示已修改的设置项，按 `r` 可将高亮行重置为默认值（在服务覆盖项上则会恢复继承全局设置）。在文本编辑器中按 `Esc` 或点击取消时，若有未保存的修改会先提示确认。所有更改均立即持久化，并在下一次请求时生效，无需重启。

实验主页的 **搜索设置**（Find settings）模式以及启用的自动结果（Auto）都会同时包含普通偏好项与设置管理器中的操作项。你可以搜索界面上显示的名称（例如 **注册服务** 或 **发布后缀**）、曾用名、稳定的配置键名或其说明文字。在其他界面语言下直接输入英文名称同样有效。选中搜索结果后只会打开其所属页面并高亮对应行，不会自动修改值或触发操作，仍需使用该页面的常规控件完成变更。返回后会回到同一主页搜索状态。有关排序和导航细节，请参阅[实验主页](home-interface.md)。

## 内容密钥验证

**设置 → 下载行为 → 下载前验证内容密钥** 默认关闭，单个服务可在 **授权与密钥库** 下单独覆盖。该功能仅在获取密钥后、开始传输前校验最终选中的加密点播（VOD）轨道；直播、仅导出（export-only）和仅生成命令（command-only）操作都会跳过校验。开头明文段（clear lead）不算作验证通过；无法得出确定结论的采样只会发出警告，不会拒绝密钥。若某个密钥库候选密钥校验失败，会依次尝试其他已启用来源，最后再向已配置的服务/CDM 请求一次。有关限制、回退规则、独立命令以及写入密钥库的安全性，请参阅[内容密钥验证](key-verification.md)。

## 配置值的存储位置

`<paths.home>/settings.json`，每个作用域对应一个顶层对象——全局使用 `@global`，其余按各服务 ID 分隔。

## 服务与主页显示

全局 **设置 → 服务** 包含全局 **许可方式**（License action）默认值、**按服务设置章节元数据**、**按服务获取标题附件**、**按服务测量实际视频码率**、**注册服务**、**主页显示的服务** 以及 **导出 manifest 类型**。UniDL 会从当前运行的包目录、源码检出目录中的 `src/unidl/services`、当前项目的 `services` 目录以及可写的 `<paths.home>/services` 目录中发现服务包，并将已注册的包显示为禁用条目。要添加新服务，请将完整的服务包（或单文件服务模块）复制到主页初始化提示中显示的可写目录，打开 **设置 → 服务 → 注册服务** 并选中它。注册操作会记录选择并提示你重启 UniDL；必须重启后新进程才会导入该服务包，注册结果才会出现在主页网格和全局搜索中。如果你不确定当前运行的是哪一份安装副本，可打开 **设置 → 文件与命名 → 高级路径**，其中 **服务目录** 显示了当前安装实际使用的服务目录，点击该行或按 Enter 即可直接打开。如果当前处于源码目录，但运行的 `unidl` 命令来自其他安装副本，请在源码目录中执行 `uv sync`（或 `python -m pip install -e .`），或者将 `UNIDL_SERVICES` 环境变量指向存放服务包的目录。主页显示列表是一个独立的多选框列表：取消勾选已注册的服务会将其从主页网格中隐藏，但在全局搜索中依然可用。如果之前注册的服务包在启动时暂时不可用，UniDL 会保留其注册记录，待下次重新发现该包时继续使用。

**导出 manifest 类型** 独立保存在各个已注册服务的 `settings.json` 命名空间中。传统/默认值为 **主 manifest**（master manifest）：原生导出会像以往一样保留原始已授权的 MPD、ISM 或 HLS 入口。若合并了多个已授权的主 manifest，则会记录所有参与合并的主 manifest URL，而不会展开它们的完整分片列表。导入时只读取这些保存下来的 URL，不会让已安装的服务重新授权新的变体。如果原始引用无法安全还原（例如内联 JSON 源或拼接时间线），则会改为保存原始源与所需轨道元数据的打包集合。缺少来源信息会直接明确报错，绝不会静默生成不完整的导出文件。

**全部媒体 manifest**（All media manifests）会保存原始的 MPD/ISM 文本或原始 HLS 媒体播放列表，以及解析它们所需的轨道元数据。该模式**不会**将解析后的分片列表、字节范围表或生成的 init 字节写入 JSON。导入时会通过常规解析器展开已保存的协议文档，无需重新请求原始主 manifest。直接媒体 URL 或原始 JSON 轨道列表仍作为源引用保存；导出本身不会下载媒体内容。

两种模式都会保留独立的 API 字幕 URL，包括未选中的语言、Normal/SDH/Forced 类型、格式、原语言标记以及必需的请求头。多个已授权档位（profile）会各自保留其请求标签、返回类型标签及轨道关联关系，即便重复轨道在选择器中已折叠为同一行也是如此。来源标签和字幕 URL 不等同于体积庞大的播放/API 响应封包：后者及展开后的 JSON 分片列表依然不会写入导出。导入时，若对应服务已安装，则会保留其自定义外挂字幕钩子；若未安装，则直接字幕源走通用交付路径。已过期或缺失的 URL 无法仅凭标签恢复，如旧导出漏掉了它们，需要重新导出。

导出模式是第三道独立的设置边界，既区别于服务端的 manifest 档位，也区别于最终轨道选择。媒体 manifest 导出会记录解析出的全部轨道，而不仅限于当次运行选中的轨道；因此只要所需内容密钥和媒体 URL 仍有效，导入后的标题就可以重新选轨。导出不会续期 CDN 授权：一旦媒体 URL 本身过期，导出文件也会随之失效。直播 manifest 绝不会被冻结为静态媒体快照；即便某个服务配置为媒体 manifest 导出，直播播放仍会保留可刷新的原始 manifest，并在日志中报告该回退行为。

导入时会根据最终选中的轨道重新计算发布后缀（release suffix）。例如，从一份 2160p HDR/DDP 的导出中只勾选 1080p SDR 与立体声 AAC，则会写出 `1080p.DEMO.WEB-DL.AAC2.0` 外加所选视频编码，不带 HDR 标签（此处 `DEMO` 代表来源的发布组标签）。新版本导出会单独保留精确的标题主体部分，因此自定义发布命名模板也能正常重建。旧版常规的点分隔、空格分隔与连字符分隔命名仍继续受支持，无需修改原导出文件。

原生导出使用格式版本 3。新的 JSON manifest 与导出文件只存储原始源文档，不再存储展开后的下载器状态。原始 MPD/HLS/ISM 文本本身就包含分片语法，UniDL 不会再把这些语法复制成 JSON 分片对象。展开后的分片数据只属于运行时解析与断点续传缓存。版本 1 和版本 2 的导出文件仍可直接从原文件读取，但其中的分片快照不会被复制到新文件中；重放这类旧导入时请保留原文件。旧版读取器会明确拒绝版本 3。

剧集批量导出会合并保存为单个 JSON 文件，以剧名与导出时间命名，例如 `Survivor_20261021_181310.json`，不含首集集号、单集标题或单集发布后缀。显式声明的批量任务从第一条导出记录起就使用这一命名；如果任务是在后续新增标题后才变为批量，系统会自动更新其默认文件名并保留最初的时间戳。每条记录内部仍完整保留各自的发布名、分集元数据、轨道与密钥。单标题导出文件名以及自定义输出路径不受影响。混合标题的批量任务会使用服务级的 `Batch` 命名；同一秒内产生的多次导出会自动附加数字后缀，不会覆盖已有文件。

每个导出文件（包括整份批量导出）大小上限为 **32 MiB**。较小的文档保持缩进排版；较大的源打包文件可能会改用紧凑 JSON 格式以满足上限。如果压缩空白后仍超过上限，导出会在替换或创建目标文件之前明确失败，已有批量文件保持完好。此时应缩小批量规模或切换为“主 manifest”模式；UniDL 绝不会为了塞进体积限制而静默截断轨道、丢弃标题或切换模式。

如果你安装的是不含任何服务包的精简发行版，主页会展示相同的导入目录并提供前往“设置”的入口。将服务复制到提示的目录中、完成注册，然后重启 UniDL 即可。CDM 配置提示与此相互独立：没有 CDM 也能注册服务，但播放 DRM 内容仍需配套的 `.wvd` 或 `.prd` 设备文件。

每一次设置变更都会在修改当下立即落盘，并采用能抵御进程异常退出的写入机制：

- **原子写入**：先写临时文件再原子替换目标文件，即使写入中途进程被强杀也不会留下残缺文件。旧实现曾直接截断原文件，而面对无法读取的配置文件时会以空字典启动——在用户看来就仿佛“所有设置被重置成了默认值”。
- **备份回退**：上一份正常文件会保留为 `settings.json.bak`，当当前文件无法读取时自动回退使用；损坏的文件绝不会被复制到备份上。
- **跨进程加锁合并**：跨进程文件锁覆盖最终读取、增量合并、备份与替换全过程，确保同时运行的另一个 `unidl` 实例或检测脚本不会彼此覆盖配置。
- **仅限所有者访问**：当前文件、备份文件、临时文件与锁文件权限均为 `0600`。

当写入失败（例如主目录只读或磁盘已满）时，错误会被记录下来而非直接抛出崩溃，便于向用户报告原因，而不是表现成“改完设置却没生效”。

```
全局（Global）       七个精简管理器：下载行为、服务、DRM 与密钥库、文件与命名、代理与 VPN、JustWatch 搜索、界面与诊断
<服务>               该服务自身的专属配置项
轨道与输出           所有服务共用的画质与输出配置项
```

每个原生服务在其专属设置区域中也保留各自的 CDM 设备行：服务每声明一种 DRM 系统，就会出现对应的 `Widevine CDM`、`PlayReady CDM`（或其他已注册系统）行。留空表示“沿用全局选择”；指定设备名称则仅对该服务生效。**设置 → DRM 与密钥库** 用于管理本地设备文件和远程 CDM 定义本身，但不会替代这些按服务指定的选择。

静态配置——如 CDM 路径、账号凭据、固定目录——**不属于**运行时设置，它们存放在 `unidl.yaml` 中。请参阅 [configuration.md](configuration.md)。

## 为什么服务设置与轨道设置分离

因为它们在请求流程中的生效时机不同。

**服务设置在发起请求之前生效**，通常决定了*你能拿到哪一份 manifest*。服务可以暴露单个档位，也可以在每个选项都对应经过验证的 API 请求时提供多选。Core/核心层会独立解析这些经服务授权返回的 manifest，合并轨道阶梯，并依据展示出来的媒体属性去除重复表示（而不是按短时签名 URL 或服务商自定义的 representation ID 去重）；Core 绝不会凭空编造档位名称，也不会根据共享轨道偏好去推导 URL。示例服务提供 `hd/uhd` manifest 档位；BBC 提供 `auto/uhd/fhd/hd`；其他服务包可能声明平台、地区或本地市场选项。这些选项体系彼此之间无法自动换算，因此由各服务自行声明，且仅在对应服务处于激活状态时显示。

**轨道设置在解析 manifest 之后生效**，直接作用于真实返回的轨道阶梯，是所有服务共用的统一选项体系。`1080` 在所有服务中含义完全一致，因为它直接匹配实际的分辨率数值。

### Manifest 档位不是轨道选择

这是两种截然不同的决策，绝不能合并到同一个设置项中：

1. **获取 manifest 档位**发生在打开 MPD 或播放列表之前。由服务自有设置决定请求服务商的哪套源档位或 URL，例如源分辨率、编码、动态范围、平台或 API 能力族。
2. **从 manifest 中选择轨道**发生在 manifest 解析完成之后。共享的 `video_quality`、`video_codec`、`video_range` 以及音频、字幕设置只从实际返回的阶梯中筛选表示（representation），绝不会去改选另一个源 URL。

例如，某个服务可以提供 `manifest_resolution`、`manifest_codec` 和 `manifest_color` 来选择源 manifest，同时共享的 `video_quality`、`video_codec` 和 `video_range` 依然可用于决定最终输出的轨道。因此，“请求 4K 杜比视界源 manifest + 输出 1080p SDR 轨道”是完全合理且有意支持的组合。只要存在服务级的源设置，服务适配代码就绝不能读取共享轨道设置来决定拉取哪份服务端 manifest。

当服务商在 manifest 之外额外返回媒体资源时，同样的边界依然适用。服务商专属的音频播放列表由该服务的源/API 契约负责选择和拉取。对于通过独立字幕 API 返回的字幕，服务应通过 `augment_tracks` 将完整清单暴露为 Core 的外挂（sidecar）轨道行；它们会与 manifest 内嵌字幕一同出现在常规选轨界面中，由共享的 `sub_langs` 筛选。`prepare_download` 负责下载被选中的外挂字幕，并通过 `Playback.mux_imports` 将本地文件路径交给原生下载器。共享设置绝不决定发起哪个字幕 API 请求。

被选中的 API 字幕也会出现在实际下载进度框中。进度框会在服务准备外挂字幕之前打开，并在后续原生音视频传输期间保留已完成的字幕行。支持字节进度的服务会上报实测字节数和百分比；旧式一次性拉取 API 则在字幕文件准备完成前显示活动状态与未知百分比。失败或跳过的准备步骤不会被标为已下载。这一机制不会增加额外的字幕请求，也不会改变服务既有的转换或混流路径。

这也是为什么无论是服务 API 选项还是命令行默认值，都不可能在返回阶梯被解析之前真实准确地选定最终码率。

服务商也可能直接返回完整的已授权阶梯，而不暴露单独的源分辨率设置。实际交付的分辨率以解析后的 manifest 为准，而不是目录页上的画质徽章。共享的 `video_quality=best` 会预选符合条件的最高表示；`track_mode=auto` 则不打开选轨界面直接接受该预选结果。服务商账号权益和 CDM 要求依然作为独立约束生效。

如果播放流程会建立服务端会话（session），对应服务必须自行负责会话续期，并在交付完成或取消后关闭会话。请参阅[播放生命周期](playback-lifecycle.md)；共享设置契约中不包含任何特定的会话端点或心跳间隔。

| `services_manager` | 管理器界面 | — | 打开 **服务**，包含服务注册、主页显示、章节元数据、标题附件、实际视频码率、许可默认值以及导出 manifest 类型。元数据与码率开关可按服务独立配置。 |

| `storage_manager` | 管理器界面 | — | 打开 **文件与命名**，统一用于编辑常规输出目录和文件名模板、预览示例发布名，以及查看敏感运行时路径（不会移动文件）。 |
| `proxy_manager` | 管理器界面 | — | 打开 **代理与 VPN**，集中管理默认路由、分片下载路由、命名代理端点以及 HTTPS 代理服务商。 |

### 结束直播录制

- **返回（Back）** 会以与到达录制时长上限相同的方式结束捕获：完成当前分片批次、关闭实时混流或执行录后混流、保存最终文件，然后返回上一界面。若录制处于暂停状态，收尾时会自动恢复；重复按返回不会取消收尾流程。如果此时正弹出密钥轮换提示，按返回会完成已经捕获的部分，并排除因密钥不可用而挂起的批次。
- **退出（Quit）** 执行快速取消，不会再启动额外的混流、解密或转码流程。已经写盘的录制数据会保留，但被中断的容器文件可能不完整，原始轨道也可能需要后续处理。
- 实时混流文件在录制期间直接显示在下载目录中，分离轨道则存放在 `<name>.recording/` 目录内。正常完成录制后，只有在最终文件提交落盘之后，系统才会按既有留存设置清理被替代的临时轨道。若遇到退出、混流失败或提交失败，已捕获的媒体都会保留在原处；收尾失败时会停留在当前界面便于检查或重试。系统只会清理自身创建的空录制目录或空文件。
- 常规 VOD 取消以及按 **VOD 方式** 下载的直播回看（DVR）沿用原有的取消与续传行为。

### JustWatch 搜索与即将上映雷达数据源

**JustWatch 搜索** 管理器将四项相关的片源发现设置整合在一起：

- **标题目录**（`justwatch_search_region`）为单一国家代码，决定标题匹配结果、本地化片名以及即将上映雷达中按地区展示的流媒体上线信息来源于哪个目录。
- **上架查询地区**（`justwatch_regions`）为地区列表。JustWatch 会按国家逐一查询播放源，用来回答所选标题在哪些地区上架。
- **即将上映数据源**（`upcoming_sources`）用于为 **定时下载** 里的“即将上映雷达”标签页选择一个或多个数据源（`JustWatch`、`TVMaze`、`AniList`、`TMDB`）。
- **TMDB API 密钥**（`tmdb_api_key`）保存可选的、经过脱敏显示的 TMDB v3 API 密钥或 v4 Read Access Token。

JustWatch 搜索界面和上架查询界面各自保留了 `Ctrl+R` 地区选择器，**定时下载 → 设置** 则将雷达数据源、TMDB 密钥、地区与海报预览开关集中在一处展示。

全局设置的一级菜单刻意只展示上述七个管理器：**下载行为**、**服务**、**DRM 与密钥库**、**文件与命名**、**代理与 VPN**、**JustWatch 搜索** 和 **界面与诊断**。上表中位于它们下方的条目均为持久化兼容键，不会在一级菜单中重复列出。

### 文件与命名

全局设置列表中只显示一行 **文件与命名**，而不再平铺六个分散的路径与模板行。它包含三个标签页：

- **输出位置** — 包含 `download_dir` 以及 `paths.subtitles`、`paths.commands` 和 `paths.exports`。保存路径时会创建目标目录，但绝不会移动已有文件。重置某一项会移除覆盖并恢复为已配置或默认位置。
- **命名模板** — 包含 `name_template_episode`、`name_template_movie`、`release_template` 和 `release_tag`，并附带剧集与电影命名预览。这些仍然是普通的 `settings.json` 键，管理器只是它们的统一界面。`episode_folder_template` 也在同一标签页编辑，用于在服务目录下控制可选的剧集子目录；它不会改动文件名，也不会移动已下载文件。
  上方的 **文件名格式** 是快速预设：**点分隔（scene 风格）** 保留传统的 `Real.Time.With.Bill.Maher.S24E29.720p...` 形式，**空格分隔** 使用 `Real Time With Bill Maher S24E29 720p...`，**分区连字符** 使用 `Real Time With Bill Maher-S24E29-720p...`。该选项只改变分隔符，具体包含哪些标题、画质、音频、视频和发布组字段仍由模板控制。
  发布模板支持 `audio`、`audio_channels`、`audio_full`、`atmos` 和 `video`。当存在明确标识为立体 3D 的视频轨道时，`{three_d?}` 会追加 `3D`；默认位置在画质动态范围标签之后，例如 `H.265.DV.3D`。该标记独立于 DV/HDR，且仅依据最终选中的视频轨道判断；自定义模板可自行调整位置或省略。其余默认字段会生成类似 `AAC2.0`、`DDP5.1.Atmos`、`H.265` 的名称。所有这些值都仅在输出选择器确认后，根据用户最终保留勾选的轨道实时计算——而非依据初始自动勾选项或完整 manifest 清单。
- **高级路径** — 展示当前运行实例的 **服务目录**、`home`、缓存/临时/日志目录、令牌（tokens）、Cookie、外部工具（helpers）、CDM 目录以及默认本地密钥库。这些路径保持只读：点击某行或按 Enter 可在系统文件管理器中打开对应文件夹（密钥库行打开的是其所在目录，而不是数据库文件本身）。绝不会移动已有文件，也不会改动任何路径设置。查看或打开路径不会创建新目录，目录不存在时仅做提示而不自动创建。若系统缺少桌面文件管理器，UniDL 会直接显示完整路径。

已安装的服务路径直接根据当前运行的包位置推导，而非基于工作目录猜测，因此源码运行、pip、虚拟环境和 uv 安装都会准确显示各自的路径。将完整服务包复制到该目录，在 **设置 → 服务 → 注册服务** 中注册，再重启 UniDL 即可生效。这一只读行不会引入新的 `paths.services` 配置键；既有的用户服务目录、自定义 `UNIDL_SERVICES` 以及项目目录发现机制均保持原样。

隐藏的兼容键对代码、既有配置文件和验证脚本依然有效。任何服务设置或轨道输出选择设置都不会被移入此管理器。

### 代理与 VPN

全局设置列表提供单独的 **代理与 VPN** 行。其路由（Routing）标签页接受空值（直连）、完整的 `http(s)://` / `socks` URI、`proxies` 中定义的名称，或服务商查询表达式（如 `expressvpn:us`、`nordvpn:us`、`surfshark:gb` 或 `windscribe:ca:toronto`）。`proxy_downloads` 单独控制原生下载器核心的分片请求是否走解析后的代理路由；UniDL 自身的 API、manifest 与许可请求仍走该路由。

该管理器支持静态 HTTP/HTTPS/SOCKS 端点池，以及来自 ExpressVPN、NordVPN、Surfshark 和 Windscribe 的 HTTPS 代理端点。ExpressVPN 使用显式的 OAuth 设备授权界面（在其服务商行上按 `l` 触发）；轮换的刷新/访问/连接令牌以仅所有者可读权限写入 `<paths.tokens>/vpn/expressvpn_tokens.json`，后续可无头自动刷新。NordVPN、Surfshark 和 Windscribe 使用保存在 `unidl.yaml` 中的手动配置服务凭据。代理服务商仅在被选中时解析，不会修改本机的系统 VPN 或默认路由。Gluetun、Proton TV 登录和 Hola 仍需要外部进程或不同的登录生命周期，不会作为静默 URI 回退。服务级的代理设置依然保留，非空时会覆盖全局路由。

无论上述设置如何配置，**每次**运行都会执行以下两件事：

- 将 UniDL 命令写入 `<paths.commands>/<service>/<name>_<timestamp>.txt`
- 将获取到的 `KID:key` 密钥对连同服务名与标题信息存入密钥库

## 轨道与输出

每个服务设置页面都会在这组共享设置之前紧邻放置一个 **授权与密钥库** 区域，用于控制该服务的许可时机，以及本地/远程密钥库的查找、存储和目标列表。一旦为某个服务显式覆写，这些设置就按服务独立生效；否则自动继承全局 **DRM 与密钥库 → 密钥库策略** 与 **服务** 中的默认值。主页远程搜索与手动添加密钥的权限仍保持全局控制。在服务策略行上按 `r` 可清除覆盖并恢复继承全局值。每行都会展示当前生效值，并标明是跟随全局设置还是服务级覆盖。显式关闭（off）以及显式清空目标列表都属于有效覆盖，不会被当作缺失值处理；仅仅打开编辑器而不改动绝不会误存继承来的默认值。

启用 **许可方式 → 最终选轨后获取许可** 时，只有最终选中的加密轨道会提供 KID/PSSH 参与密钥库查询与许可请求，未选中的 manifest 变体不会被查询或请求许可。

**杜比视界混合输出（Dolby Vision hybrid output）** 是一项独立的下载后处理转换，既不是 manifest 档位，也不替代最终轨道选择。启用后，Core 会把配对的 DV/HDR10 素材加入选中阶梯，使两路素材都走正常的服务自有许可与密钥库流程。两份解密文件下载完成后，由 `ffmpeg`、`dovi_tool` 和 `mkvmerge` 将 DV RPU 注入 HDR10 基础层，再将合成后的单条混合视频送入最终混流。该功能默认关闭，直播/回看流会忽略此设置；若缺少任一层、帧率/时长/帧数不兼容或缺少 HEVC 数据，则会安全地保留原始轨道不动。DV 输入选取的是可用分辨率最低的 DV 层，无需与 HDR 基础层分辨率一致。系统中必须安装 `dovi_tool` 且位于 `PATH` 中（或通过 `UNIDL_DOVI_TOOL` 指定路径）。初始实现使用 dovi mode 3 规范化 RPU 并保留源画面几何尺寸，不会凭空生成 L5/L6 裁切元数据。

本区域即 **轨道输出选择**（Track output selection），用于决定原生下载器核心从已解析的轨道中下载、保留并混流哪些轨道。这些设置本身不是许可轨道选择器，绝不能静默决定服务的 PSSH 种子、请求的 KID 或许可档位/API 路由。

这一边界适用于下表中的全部设置项。具体而言，`video_quality`、`video_codec`、`video_range`、音字幕设置以及交互式勾选框都只决定最终输出。把输出从 720p 改成 4K、把 AAC 改成 Atmos 或切换语言，都不会隐式改写服务的许可获取方案。

如果某个平台存在可配置的许可轨道规则，它会在该平台自己的服务设置区中单独列出，并使用明确的名称（例如 `license_tracks`、`license_profile` 或 `pssh_video_profile`）。两类设置提供的画质或轨道分类看起来可能相似，但即使默认值恰好一致，它们也始终保持独立。默认情况下，许可获取在打开交互式输出选择器之前就已完成，因此后续选定的输出表示并不是许可请求的运行时输入。

**许可方式 → 选轨后（After）** 是显式例外：它会等待最终选择器确认，然后只把最终选中的加密轨道交给 Core 执行密钥库查询与许可解析。**选轨前（Before）** 使用常规的选轨前全量清单。**自定义（Custom）** 允许显式支持的服务自行决定方案，未声明支持的服务不会提供该选项。即便如此，这也不允许服务去读取共享画质或语言设置来决定服务商 API 请求。有关优先级、兼容性以及 DASH/HLS/ISM 适用范围，请参阅[许可方式](drm.md)。

`track_mode` 决定解析完阶梯后是弹出界面等待确认，还是静默直接应用。在 `interactive` 模式下，打开选择器时已按自动规则预先勾选，直接按 `enter` 即可接受。这些勾选框依然只控制交给原生下载器核心输出的轨道。在默认 DRM 顺序下，选轨界面出现在获取密钥之后；开启显式兼容开关（选轨后获取许可）时，Core 也会根据最终勾选出的轨道对象定位各自的 KID/初始化数据，但绝不会把任何勾选框变成服务档位选择。

`output_scope`（输出范围）控制自动选择允许选取哪些媒体类型。`package` 是兼容默认值，和以往一样同时选择视频、音频与字幕；`video`、`audio` 和 `subtitle` 适合批量任务，例如在不打开选轨器的情况下收集每一集的字幕；`custom` 则读取逗号分隔的 `output_types` 值。随后由 `video_selection` 以及既有的 `audio_selection`/`subtitle_selection` 决定是只取最佳匹配轨道还是保留所有通过筛选的轨道。收窄后的输出范围会禁用自动混流，使每条选中的轨道保留为独立输出并附带区分轨道的文件名。

选定的输出范围及 Best/All 规则会写入保存的命令元数据与原生导出文件。重新运行已保存的命令时会直接使用当时精确选中的轨道索引；导入原生导出时则会先恢复其保存的输出范围，再执行自动选择。

当自动规则没有匹配到轨道时，单标题任务会打开常规手动选择器：已匹配的媒体类型保持勾选，未匹配的类型保持未勾选，用户只需修正出问题的那部分即可。在批量任务中，该标题会被记录为跳过并继续处理后续标题；批量任务绝不会卡在无法跨集共用的选轨界面上。

自动选择会将语言、编码、档位（profile）、声道数和字幕类型视作逻辑与（AND）关系的硬过滤条件。`best` 或 `worst` 只负责对通过过滤后剩余的轨道排序，绝不会放宽过滤条件。如果没有任何轨道符合条件，UniDL 会报告具体条件并打开常规轨道选择器，让用户手动选择而不必取消交付。`Atmos` 属于音频档位（profile）而非编码；`audio_codec=atmos` 仍作为旧版别名保留，等效于 `audio_profile=atmos`。语言匹配支持精确 BCP-47 标签及其主语言（例如 `es-419` 可匹配 `es`），但不会对 `und` 或未知的服务商标签做猜测。

字幕转换在进行时间轴修复和去重时会保留每条字幕的定位信息。选择 **ASS + MKV** 可保留常见的顶部/底部位置、坐标定位及基础样式强调。SRT 会保留常见的 `{\an8}` 顶对齐扩展，实际效果取决于播放器支持，无法表达完整布局。WebVTT 会保留 cue 设置、`STYLE`/`REGION` 块及标记。Original（`raw`）原样保留下载的字幕不做改动。MP4 需要兼容的 `mov_text` 字幕，混流时可能会丢失定位信息。请参阅 [track-selection.md](track-selection.md)。

`audio_format` 适用于纯音频标题和纯音频（`audio`）输出范围。可选列表在运行时从原生下载器核心动态探测，因此设置面板绝不会展示当前引擎并未提供的编码器。请参阅 [audio.md](audio.md)。

`default_audio` 用于控制混流后的 MKV/MP4 中的默认播放音轨，与负责决定下载哪些音轨的 `audio_langs` 相互独立。可选 Auto、Original 或单个语言标签。若找不到匹配项，系统会发出警告并回退到 Auto，绝不会额外添加轨道或取消下载。批量任务中每个标题会在各自最终选轨完成后分别解析默认音轨偏好；导出文件和保存的命令都会保留该设置。有关优先级、地区匹配、直播录制和容器限制，请参阅 [track-selection.md](track-selection.md)。

`default_subtitle` 是对应的混流默认字幕设置，独立于决定下载范围的 `sub_langs` 和 `subtitle_kinds`：后两者决定下载什么，此项只把已选中字幕中的某一条标记为容器默认字幕。支持 Auto、Original 以及单个语言标签，并涵盖服务提供的外挂字幕；未匹配时会回退到已选中的原语言字幕，或在发出警告后不设默认标记。请参阅 [track-selection.md](track-selection.md)。

`subtitle_output` 控制选中字幕的输出去向：`muxed` 嵌入最终容器，`external` 作为外挂文件保存在音视频输出旁、容器内仅混流音视频，`none` 则完全跳过字幕下载。服务级的值可以继承全局选择。

### 修改或移除 `drop_video` 前请先阅读

进度条预览（trick-play）和缩略图雪碧图阶梯本质上也是视频轨道，而且往往具有很高的纵向分辨率。真实案例：一条 `1280x1440` 的缩略图轨道在仅按高度判断“最佳”时，可能会压过真正的 `1920x1080` 正片视频。默认正则会把这类轨道排除在画质选择之外，并且加上了词边界限制，避免像 `Strickland` 这样的正常标题被误判成 `trick` 轨道。已有配置中如果还保留着旧默认值 `trick|thumbnail|image`，会在运行时自动升级。旧版脚本传递 `-dv 'trick|thumbnail'` 也是出于同样的原因。

## 章节元数据

**获取章节元数据** 可按服务独立配置，既可在对应服务自身设置中调整，也可在 **设置 → 服务 → 按服务设置章节元数据** 中统一管理，两个入口写入的是同一个服务作用域配置值。未显式配置的服务会继承旧版全局值（全新安装默认为开），因此升级后不会静默重新开启此前禁用的章节请求。关闭该项会在创建播放对象之前跳过章节接口调用和可选章节字段；`embed_chapters` 依然是独立的按服务输出开关，仅控制是否将章节混流进容器。章节元数据遵循尽力而为（best effort）原则：响应缺失、格式异常或暂时不可用时只会降级为无章节（服务支持报告时会给出警告），绝不会阻断播放、许可获取、下载或混流。

## 实际视频码率

打开 **设置 → 服务 → 按服务测量实际视频码率** 可修改全局默认值（全新安装默认为开）或单独开关各个已注册服务；各服务自身的设置页也提供同一个 **获取视频真实码率** 开关，两者保存的是同一个服务作用域键 `fetch_actual_bitrate`。未设覆盖的服务跟随全局默认值；修改全局行不会覆盖已单独设置的服务。在服务行按 `r` 可移除覆盖，在全局行按 `r` 可恢复默认的开启状态。此前在 **下载行为** 中保存的全局偏好在迁移后仍会被保留。

码率测量依然只在最终视频选轨完成、下载详情界面已经显示之后才运行。它只抽样已选中的视频轨道，不会探测整个 manifest 清单，并会借助同一次探测修正色彩范围标签与最终文件名，不会给初始 manifest/轨道列表加载增加任何探测请求。关闭后会完全跳过探测，沿用 manifest 自带的码率与色彩元数据。直播录制不进行探测；不可用或不可靠的采样会被忽略，不会导致下载失败。

## 标题附件

**获取标题附件** 可在各服务自身设置或 **设置 → 服务 → 按服务获取标题附件** 中独立配置。服务在请求可选的海报、缩略图或艺术封面之前应先检查 `fetch_attachments_enabled()`，再将结果写入 `Playback.attachments`。UniDL 会在章节与歌词旁提供附件预览。

**下载标题附件** 是位于 **轨道与输出** 下的独立按服务开关（`download_attachments`，默认开启以保持既有行为）。它只会在媒体下载成功后，将可用附件保存到单独的 `<save name>.attachments` 目录中。开启“获取”同时关闭“下载”，可以在不自动落盘附件文件的前提下保留附件计数、预览、保存的命令元数据与导出信息。“下载”开关既不会开启元数据获取，也不会删除已有文件，亦不影响手动打开预览。附件属于辅助资源：附件下载失败绝不会导致本已成功的媒体下载失败，附件也绝不会被混流进媒体文件中。

## 声明服务设置

```python
from ...core.settings import Option, Setting

SETTINGS = [
    Setting(
        key="dma",
        label="Live market (DMA)",
        kind="choice",
        options=[Option("auto", "Auto from account"), Option("501", "New York (501)")],
        default="auto",
        help="Which local station feed to request for live TV.",
    ),
]
```

`kind` 支持 `choice`、`bool`、`text` 或 `int`。`resets_session=True` 用于标记会令当前登录失效的设置项；设置面板会将其标为 `(signs out)`，并在值改变时由 Core 调用 `logout()`。平台、API 版本、地区、manifest 或交付方式选择器不属于认证失效操作：它们必须保持其他变体的令牌与 Cookie 完好无损，因此必须保持 `resets_session=False`。只有用户显式登出（或服务商明确返回使当前所选会话失效的响应），才能清除认证状态。

只声明服务真正支持的设置项。`platform`、`region` 和 `dma` 在存在时属于路由/档位选择器，而非输出分辨率设置；切换它们时必须保留各路由各自独立的令牌与 Cookie 缓存。普通账号登录与电视运营商（TV-provider）登录的区别归属于服务主页的 `Sign in` 操作。

公开示例服务声明了取值为 `hd` 和 `uhd` 的 `manifest_profile`。它在播放授权之前选择服务商源档位，不会替代解析返回 manifest 后所使用的共享 `video_quality`、`video_codec` 或 `video_range` 设置。

## 读取设置

```python
self.settings.get("dma")            # 服务自有设置
self.settings.get("video_quality")  # 共享设置
self.settings.get("debug")          # 全局设置，经由父作用域解析
```

同一个对象承载三个作用域，按回退顺序逐级解析。当服务声明了与全局同名的键时，大多数服务设置会遮蔽（shadow）全局键；而共享策略键（`fetch_chapters`、`fetch_actual_bitrate`、`license_action`、密钥库闸门以及密钥库目标列表）则改为默认继承全局值，直至服务显式保存覆盖值。显式保存 `false` 或空目标列表同样视为覆盖。在继承的服务策略行上按 `r` 即可清除覆盖并恢复回退到全局值。

## 存储格式

保存在 `<paths.home>/settings.json` 中，按服务 ID 作为顶层键，全局层级保留使用 `@global`。通过代码传入的覆盖值（供验证脚本使用）仅对单次运行生效，不会写入磁盘。
