# 安全策略

[English](../SECURITY.md) | [简体中文](SECURITY.md)

unidl 会处理高度敏感的本地数据：账号凭据、浏览器 Cookie、会话令牌、CDM 设备文件与密钥材料、内容密钥、远程密钥库令牌、导出命令文件以及调试日志。凡涉及上述任意数据的泄露，即使未牵涉源码层漏洞，也均按安全问题处理。

## 报告安全漏洞

请通过代码托管平台的私有安全报告渠道提交漏洞。如果未开启私有报告渠道，请在提交公开 Issue 前私下联系维护者。公开 Issue 中绝不可包含可用凭据、Cookie、Bearer 令牌、设备文件、CDM 或密钥库密钥、完整的 `KID:key` 密钥对、私有 URL 或未脱敏的日志。

报告时请附上受影响的版本或提交号、操作系统、影响范围、最小复现步骤，以及触发该问题是否需要恶意配置、异常服务响应或特定本地文件。请将所有密钥替换为稳定的占位符，并将响应体精简到足以复现问题的最小结构。

本项目处于活跃开发阶段，安全修复均面向当前主线代码，目前尚未提供独立维护的长期支持（LTS）版本。

## 敏感文件与默认安全策略

- 在支持 POSIX 权限的平台上，运行时设置、令牌、Cookie、CDM 文件、密钥库、日志、命令文件和便携导出文件均强制设为仅所有者可读写（文件 `0600`，所在状态目录 `0700`）。包含远程地址、令牌或其他密钥的 YAML 文件应妥善保密，提交代码前务必移除其中的敏感信息。
- 严禁提交 `tokens/`、`cdm/`、`db/`、`cookies/`、`helpers/`、命令导出文件、日志、`.wvd`、`.prd`、`.mld`、WASM 设备模块以及浏览器导出的 Cookie 文件。
- 调试模式为便于排障，会保留签名 manifest URL 和内容密钥的原文；API 请求头、账号字段、Cookie 和 Bearer 令牌会被脱敏，许可证请求/响应体仅在许可证请求失败后记录。分享调试日志前请先人工复核，因为签名 manifest 和内容密钥依然敏感，可能被用于直接访问媒体内容。
- TUI 中的**分享日志**（Share log）功能会保留完整的签名 manifest 链接与内容密钥。尽管它会对其他可识别凭据打码，其输出仍不可未经审查直接公开发布。请先删去签名链接与密钥，或仅发送给受信任的对象。
- `PartnerAuthorization` URL 是一次性 Bearer 凭据，只能经由核心层的内存交接通道传递，必须立即消费，绝不可渲染、记录日志、序列化、入队或落盘。详见 [partner-authorization.md](partner-authorization.md)。
- 远程 CDM 与 API 密钥库务必使用 HTTPS。令牌属于 Bearer 凭据；`no_push: true` 仅禁止写入，并不能使不受信任的密钥库变得安全。
- 远程 CDM 能看到初始化数据与许可证响应；可写的远程密钥库能看到获取到的内容密钥。请仅配置您自己控制或完全信任的端点。
- 服务代码统一经由类型化的原生服务契约运行。不要引入绕过认证、DRM、密钥库或审计边界的替代执行路径。

若发生密钥或设备文件泄露，请立即删除已外泄的文件或记录，在签发方轮换或吊销凭据，更换远程密钥库/CDM 令牌，尽可能使缓存会话失效，全部处理完毕后再视需要发布脱敏后的事件说明。

## 适用范围

安全报告涵盖凭据或密钥泄露、不安全路径处理、命令注入、不受信任的外部工具执行、跨服务 Cookie/请求头泄漏、远程 CDM 或密钥库认证绕过，以及密钥库机密性或完整性破坏。

服务停机、目录接口变更、地区限制以及账号权益不足通常属于兼容性问题，除非其同时造成敏感数据泄露或篡改。至于用户是否获得下载特定媒体的授权，属于法律或账号合约范畴，不属于软件漏洞。
