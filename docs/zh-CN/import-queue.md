# 混合导入下载队列

[English](../import-queue.md) | [简体中文](import-queue.md)

在导入列表中选择首行加粗入口 **导入 → 跨文件批量下载**（Import → Mixed download queue）。该队列可将来自不同导出文件、不同服务和不同媒体类型的单个标题组合起来顺序下载，而无需把它们的 manifest、密钥或服务设置合并成新文件。

## 构建与运行

1. 将受支持的导出 JSON 文件放入导出目录。按 **Ctrl+O** 可打开该目录，按 **Ctrl+R** 可刷新文件列表。
2. 在左侧选择一个导出文件。按 **Space** 勾选标题，按 **a** 全选，按 **n** 清空勾选。按 **Enter** 将勾选内容加入队列；未勾选任何条目时，按 **Enter** 会加入当前高亮的标题。按 **Back** 返回且不添加任何条目。
3. 对其他文件重复上述操作：例如先选剧集的第 1、3 集，再选另一个服务的一部电影，最后选一张专辑的第 1、4、5 首曲目。
4. 在右侧核对队列。点击 **上移 / 下移**（或按 **Ctrl+Up / Ctrl+Down**）可调整高亮条目的顺序；**移除 / Delete** 删除该条目；**清空** 则清空整个队列。
5. 点击 **开始下载**（Start queue）或按 **Ctrl+Enter**，各标题将按界面显示的顺序依次下载。

底部操作栏为紧凑单行布局：左侧是队列编辑按钮，右侧是 **开始下载**。在较窄的窗口中，顺序调整按钮仅显示箭头图标，完整标签通过悬停提示查看。当前不可用的操作会置灰显示（例如将首个条目上移或将末尾条目下移）。队列为空时会展示添加标题提示；在浅色与深色主题下，文件列表与队列行都会将标题与来源元数据分两行展示并自适应宽度。

各文件按确认添加的先后顺序追加到队列。在单次确认添加内，多个标题按导出文件中的原始顺序排列，而非勾选复选框的先后顺序。重复添加同一文件中的同一条目不会产生重复项；来自不同文件的条目即便标题、ID 或发行名称相同，也仍会作为独立项保留。

## 独立的交付上下文

队列中的每一项都会完整保留各自来源的格式、manifest、请求头、代理配置、导出密钥、选轨/输出意图、章节、附件与歌词。队列准备过程不会修改原始导出对象或磁盘上的导出文件。

- **UniDL 原生导出文件**：若本机已安装来源服务，则与普通导入一样，继续沿用该服务的设置与交付钩子。
- **未安装来源服务时**：原生导出文件自动采用可移植的通用交付方式。
- **第三方导出文件**：始终采用通用交付方式。其中的服务标签绝不会授予访问已安装服务账号、Cookie、外部工具（Helper）或获取许可证的权限。

每个标题都遵循各自来源对应的轨道选择、输出格式、命名规则与保存目录设置。导入操作始终执行下载：即便在“选轨后操作”偏好中配置了保存命令/导出文件，也不会替代这里的下载流程。若开启了交互式选轨，仍会逐个标题询问，构建队列不会静默切换为自动模式。

签名 URL 可能过期、密钥可能不完整，原生自定义交付钩子也可能依赖本机安装的外部工具。将标题加入队列时，UniDL 不会联系任何服务去刷新链接或重新授权。

## 错误处理、导航与重试

单个标题下载失败时会被记录，随后自动继续执行下一项。重试失败项时会恢复该标题原始的服务上下文，绝不会错误沿用上一个下载任务留下的上下文。已完成和待下载的条目保留现有的队列详情查看能力。

暂停、恢复、跳过、返回（Back）和退出（Quit）均沿用现有的交付控制逻辑。按返回会离开当前导入会话并回到队列构建器，之前的勾选与顺序保持不变；再次按返回才会回到导入列表。退出则保持正常的应用退出行为。未设置停止时长的直播流会持续录制直至手动停止，队列中排在其后的条目会一直等待。

混合导入队列是当前界面内的内存队列，并非持久化的后台定时任务调度器。刷新导出文件列表时，已入队的来源快照不会丢失。点击开始会从头运行当前显示的整个队列（再次点击也是如此）；如果只想重试失败或已取消的条目，请使用交付界面的重试操作。

该队列复用了共享的密钥库集合与交付引擎，但服务设置和生命周期归属仍按来源隔离。每个标题的下载诊断日志遵循当前活跃服务的策略，混合队列不会把某个来源的会话调试策略强加给其他无关服务。
