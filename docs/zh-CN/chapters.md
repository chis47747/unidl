# 可选章节

[English](../chapters.md) | [简体中文](chapters.md)

章节（Chapters）是服务提供的可选元数据。没有章节接口的服务无需做任何处理，既不需要声明能力标志，也不必实现空方法。每个服务的 **获取章节元数据**（`Fetch chapter metadata`）设置决定是否发起章节请求或消费可选响应字段；在单独保存该服务的值之前，它继承全局 Services 策略（实际默认为开启）。每个服务的 **在最终文件中嵌入章节**（`Embed chapters in the final file`）是独立开关，只在获取到章节元数据后控制是否写入封装容器。可通过 **Settings → Services → Chapter metadata by service** 或服务各自的设置页修改采集开关，两处入口修改的是同一个持久化配置。在某服务显式配置之前，为兼容旧配置会继承早期的全局章节偏好；修改一个服务的设置不会影响其他服务。当内容方把转场或分段元数据直接打包在必需的播放响应中时，关闭采集模式会保留该主请求不变，但不解析也不挂载可选章节字段——既保证内容方主响应契约稳定，又维持一致的用户可见策略。

## 服务层约定

当服务的播放 API 返回章节数据时，在服务 API/模块中完成格式转换，并将 `Chapter` 列表挂载到输出的 `Playback` 对象上：

```python
from unidl.core import Chapter

playback = Playback(
    title=title,
    save_name=self.save_name(title),
    manifest_url=source.url,
    chapters=[
        Chapter(start_ms=0, end_ms=82_000, title="Opening", kind="intro"),
        Chapter(start_ms=82_000, title="Main story"),
    ],
)
```

仅当 API 明确以秒为单位时才使用 `Chapter.from_seconds(...)`；Core 中的字段始终以毫秒计。`title` 是面向用户的导航标签；`kind` 是可选的展示提示（如 `intro`、`recap`、`credits` 等），绝不用于控制广告过滤或自动跳过。

`end_ms` 可选。Core 会对章节排序、去除完全重复的条目，并根据下一个节点或已知媒体时长推导缺失的结束时间；同一时间戳下不同标题的条目会被保留。章节元数据属于尽力而为的辅助信息：接口超时、字段缺失或单个可选条目格式错误都必须仅记录日志并降级为空列表或部分列表，确保主流程继续走完播放解析、DRM、下载与混流。务必对解析逻辑进行离线测试，防止可选元数据问题升级为阻断整个标题的致命错误。

不要用 `Title.data` 代替章节字段。`Title.data` 属于服务私有数据，Core、导出流程及原生混流边界都无法访问。

## 展示与输出位置

当服务 API 实际返回了章节信息时，选轨器和下载界面都会在节目名称旁展示紧凑的章节数量——例如在 `Tracks · Reacher.S04E04.Karambits.and.Pieces` 旁显示 `3 chapters`。

点击该计数、按 `c` 键或使用交付界面的 `Chapters` 控件即可打开弹窗：

- 按序号列出各章节的起止时间、持续时长、可选类型以及片段标题；
- 界面可见 `✕` 按钮（同样支持 `esc` / `^b`）用于返回原界面；
- 正在进行的下载或录制不会被暂停、取消，也不会被全屏接管遮挡。

交付详情区块仍会直接预览 1 到 3 条章节，较长的章节列表则显示总数并提示打开弹窗查看。仅保存命令模式会在结果卡片中展示有限预览，而保存下来的命令文件包含全部章节。

导出文件会完整保留结构化章节列表。执行真实点播下载时，Core 会写出稳定的外挂 JSON 文件，原生下载器在最终混流时将其嵌入容器：传递给 FFmpeg 时转为 FFmetadata，传递给 mkvmerge 时转为 OGM 章节文本。每个服务的 **Tracks and output**（轨道与输出）设置中都包含默认开启的 **Embed chapters in the final file**（在最终文件中嵌入章节）。关闭该项会跳过外挂输入和混流嵌入，但报告、命令元数据与导出文件中依然保留章节信息。`--no-mux` 依然表示不写入任何容器元数据。

章节仅面向有限时长的音频和视频交付。直播服务可以在报告中展示章节，但不会事后用静态章节文件改写直播管道混流产物。

## 服务测试要求

- API 时间戳正确转换为毫秒并保持单调递增；
- 章节响应为空或缺失时，常规播放流程不受影响；
- 服务的 `fetch_chapters=off`（或继承的旧版全局关闭状态）不会调用可选章节接口，也不会消费可选响应字段；
- 接口报错或可选章节条目畸形时，依然正常产出 `Playback` 并顺利进入 DRM/下载/混流阶段；
- Unicode 与 RTL（从右到左）标题原样保留；
- 末尾缺失的结束时间可依据标题或 manifest 时长自动推导；
- 仅保存命令、导出和实际下载三条路径保留完全一致的章节数量；
- 长章节列表在弹窗中打开并可在矮终端内滚动，不影响日志尾随滚动行为，也不中断进行中的下载。
