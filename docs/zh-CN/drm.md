# DRM 系统

[English](../drm.md) | [简体中文](drm.md)

UniDL 通过单一的强类型 DRM 边界支持 Widevine、PlayReady 与 MonaLisa。服务声明自己支持的系统并全权负责许可证请求；Core 负责加载 CDM、生成 challenge、解析响应并返回内容密钥，绝不替服务猜测服务商端点或代发许可证请求。

## 支持的系统

| 维度 | Widevine | PlayReady | MonaLisa |
|---|---|---|---|
| 设备文件 | `.wvd` | `.prd` | `.mld` 及其引用的 wasm |
| 初始化数据 | PSSH box | WRM 头 / XML | 服务票据 |
| Challenge | 字节串 | SOAP challenge | 无 |
| 响应 | 许可证字节串 | SOAP 许可证 | 本地解包 |
| 实现模块 | `core/cdm.py` | `core/playready.py` | `core/monalisa.py` |
| 远程 CDM | 可选 | 可选 | 不支持 |

选定的设备必须与所请求的 DRM 系统匹配：Widevine 设备文件无法响应 PlayReady 请求，反之亦然。设备选择器会校验文件扩展名与设备元数据；像 `l3` 这样的文件名仅仅是标签，不会改变设备实际报告的安全级别。

## 由服务负责的许可证传输

每一次联网 DRM 交换均由服务包自行实现。基类钩子默认 fail-closed（未实现即拒绝），因此服务不会静默回退到任何共享 POST 逻辑：

```text
Core：加载设备 -> 构造 challenge -> 调用服务钩子 -> 解析许可证 -> 返回密钥
服务：决定端点、请求头、鉴权方式、请求体与响应解包
```

服务钩子可以使用自身的 Cookie、令牌、代理、设备身份与会话上下文。当服务经验证的策略需要处理多个初始化数据对象时，Core 可能会多次调用该钩子，但每一次请求依然走同一个服务自有钩子。远程 CDM 仅替换 challenge 生成与许可证解析步骤，绝不会把许可证 URL 或账号凭据搬进 Core。

## 保持三类选择彼此独立

以下三类决策必须保持独立：

1. **Manifest / 源配置（Manifest/source profile）** — 服务侧设置，用于在解析前决定请求服务商的哪份资源（例如编码格式、色彩范围或 API 配置档）。
2. **许可证 / PSSH 方案（Licence/PSSH plan）** — 服务自有的 DRM 策略，用于决定哪些初始化数据受授权。如需开放配置，应作为独立的 `license_*` 或 `pssh_*` 设置暴露。
3. **最终输出轨道（Final output tracks）** — 共享轨道设置及交互式轨道选择器，在 manifest 解析完成后生效。

调整输出画质、编码、动态范围或语言时，不得改写服务的端点、manifest 配置或许可证方案。反之，服务的许可证方案也不得改变用户最终下载的轨道。当一个服务提供多组分辨率标签相近的清晰度阶梯时，这一区分尤为重要。

## 许可方式（License action）

可在**设置 → 服务 → 许可方式**中选择全局默认行为，也可在单个服务的**授权与密钥库**分区中单独覆盖。

| 方式 | 触发时机与覆盖范围 |
| --- | --- |
| 最终选轨前获取许可 | 在输出选轨器之前执行。Widevine 通常使用默认/首个顶层 PSSH；PlayReady 会收集并去重完整加密轨道清单中的所有头信息，包括缺失的初始化分片数据。 |
| 最终选轨后获取许可 | 在自动或手动最终选轨之后执行。Widevine 与 PlayReady 均仅针对最终选中的加密轨道，包含对应的媒体播放列表与初始化分片。 |
| 自定义许可 | 仅在服务显式声明支持时显示。由服务自行决定覆盖范围、初始化数据及请求组织方式，并可显式将方案推迟到选轨之后执行。 |

全局选项只提供“最终选轨前”和“最终选轨后”，不提供“自定义许可”。声明了自定义许可的服务在用户显式保存全局或服务级策略前，会保留其自定义的默认行为。服务级显式策略优先级最高；在服务设置行按 `r` 可清除覆盖，恢复为全局显式策略（若无全局显式策略，则恢复服务默认值）。旧版 `license_after_tracks=true/false` 设置仍可兼容读取为选轨后/选轨前，包括显式的 `false` 以及改名后的服务作用域。保存或重置新选项会自动清理过时的旧覆盖项；仅打开设置界面不会修改任何配置。

“最终选轨后获取许可”同时适用于 DASH、HLS 与 ISM。Core 会精确映射 DASH Representation、读取确切选中的 HLS 媒体播放列表，并在查询密钥库或打开本地/远程 CDM 前剔除过时的全阶梯初始化数据，绝不会因为某个未选中的 HLS 变体排在第一位就顺手拉取它。若选中的轨道共用同一个多 KID 头，该头会原样发送：响应中顺带返回的其他密钥会被保留，但不会扩大所需的密钥库覆盖范围，也不会引发额外请求。ISM 可能只声明一个共享 `ProtectionHeader`；在缺乏按轨道归属信息时，Core 会保留这一共享作用域，而不会凭空编造更细粒度的映射。

合并后的多 Period DASH 轨道会为每个 Period 保留精确的 AdaptationSet/Representation 标识。选轨后的 Widevine 与 PlayReady 初始化数据提取都依赖这些 Period 内部标识，因此 Period 间的重新编号既不会漏掉靠后选中的段落，也不会因为恰好共享同一 KID 而误把其他清晰度变体拉进来。

Widevine 在“最终选轨后”模式下会对每个不同的必选 PSSH 分别发起独立交换，并原样保留其载荷。已被密钥库覆盖的请求会被跳过；单次多密钥响应若顺带覆盖了后续对象，后续便无需重复请求。若仍有选中的密钥缺失，则会直接报告许可证错误。未加密轨道、纯字幕选择、预提供的密钥以及 MonaLisa 的本地票据路径都不会额外引入 CDM 交换。

自定义钩子必须准确描述自身的实际许可覆盖范围，而不能把无关的整张轨道阶梯留作密钥库覆盖要求。只要自定义初始化方案提供了 KID 列表，Core 就会以之为准。选择标准的“选轨前”或“选轨后”模式会绕过显式声明的自定义规划器与自定义解析器，同时继续保留服务已认证的许可证传输路径。未显式声明的旧版钩子仍沿用原有兼容路径。

## PlayReady 的 PSSH 与 KID 处理

对于常规 DASH 或 Smooth Streaming PlayReady 服务，默认契约是覆盖整个 manifest 所需的密钥：

1. 解析完整的已授权 manifest，收集所有 PlayReady `ContentProtection` 条目。
2. 按文档出现顺序对原始 PSSH 对象去重。
3. 将其解析为 WRM 头，并把声明相同规范 KID 集合的头合并去重。KID 比较必须统一使用 `UUID.hex`，绝不能比较编码格式各异的原始字符串。
4. 对剩余每个头分别建立独立的 CDM 会话，并通过服务许可证钩子发送请求。
5. 按 KID 合并返回的密钥，并验证整个加密轨道清单已被覆盖。已被密钥库覆盖的头会直接跳过。

当前使用的 pyplayready 接口每次 challenge 只能返回对应那个头所关联的密钥，因此为每个未覆盖的独立头分别发一次请求是有意为之。若服务端返回明确的限流或策略拒绝，流程会立即停止后续重试并上报已收集到的密钥。单个头失败不会掩盖其他头已成功拿到的密钥；只有当必需的加密清单仍未覆盖完整时，整次交换才会判定失败。

部分 HLS 主播放列表本身不含 PSSH，而是将其放在各媒体播放列表中。面对这种结构，服务必须先按经验证的许可证轨道方案执行，仅拉取获授权的播放列表、对初始化数据去重并请求对应密钥，切勿因为主播放列表里列出了所有清晰度就逐个遍历。

如果某个服务的原始实现原本就采用不同的 DRM 模型，应当保留其原有实现。上述规则旨在守住经验证的服务契约，而不是强行把所有服务的请求次数拉齐。

## Widevine 请求

“最终选轨前”通常只发送一次默认 Widevine challenge；“最终选轨后”则可能针对多个不同的已选 PSSH 依次发送请求，直到所需的选中 KID 全部覆盖即停。自定义模式由服务自行掌控请求方案。无论哪种模式，每一次许可证请求仍旧经过服务的认证传输层，远程 CDM 不会取代这一层。

直播场景下，新出现的 KID 会沿用服务声明的初始化数据路径。Core 会尽可能复用缓存密钥，绝不凭空构造第二个端点。如果确实出现需要人工介入的新密钥，直播流程会暂停在显式的密钥替换提示处，而不会静默拿着无关密钥继续下载。

## 设备身份、会话与清理

部分服务商会将许可证与客户端身份、设备类型、账号或播放会话绑定。服务必须在构造 challenge 之前选定好该身份；打开会话后再只替换 URL 是无效的。

如果播放 API 需要开启监控会话、并发槽位或心跳会话，其生命周期由服务全权管理：在受权播放工作开始前即刻建立，并在最外层 `finally` 块中完成关闭，覆盖 manifest、许可证、命令导出、下载、取消与异常等全部路径。Core 绝不会代发心跳请求。修改服务、API 或配置档设置不属于认证失效，必须保留其他变体对应的 Cookie 和令牌。只有显式退出登录，或服务商响应明确宣告当前所选会话已失效时，才可以删除凭据。

## 与 Key Vault（密钥库）的协作

密钥库是以归一化 KID 为键的缓存层。Core 可先从选定的密钥库满足部分或全部需求，再只向服务请求缺失的 KID。新换回的密钥会附带服务与标题来源信息写入密钥库。密钥库的读写绝不会修改服务的许可证 URL，也不会绕过其传输实现。

远程密钥库属于主动启用项，与远程 CDM 彼此独立：远程密钥库负责存取密钥，远程 CDM 负责执行 CDM 密码学操作，二者都不是共享许可证传输通道。

## 故障排查顺序

遇到问题时，请按以下顺序排查错误：

1. **设备不匹配** — 所选设备文件的扩展名或 DRM 系统不对，或者设备的安全级别无法满足当前服务配置档要求。
2. **初始化数据不匹配** — PSSH/WRM 头缺失、损坏，或来自不同的 manifest / 配置档。
3. **服务拒绝** — 认证态、订阅权益、地区限制、设备身份或请求结构被服务自有端点拒绝。
4. **CDM / 解析器失败** — 服务响应已被接受，但 challenge 构造或返回的许可证无法解析。

务必确保日志已脱敏。绝不要提交设备文件、Cookie、令牌、许可证响应体、签名 URL 或 `KID:key` 密钥对。确定性的离线测试应当在不访问真实服务商的前提下，覆盖服务钩子、所选配置档、PSSH/KID 去重以及会话清理逻辑。
