# 内容密钥验证

[English](../key-verification.md) | [简体中文](key-verification.md)

**下载前验证内容密钥**是一项可选的、尽力而为的点播（VOD）预检功能，默认关闭。你可以在**设置 → 下载行为**中全局启用，也可以在单个服务的**设置 → 授权与密钥库**中单独覆盖。在保存服务级覆盖前，服务沿用全局值；重置服务设置后会恢复继承。

## 执行时机

整体执行顺序为：确定最终输出轨道 → 按现有许可方式获取所需密钥 → 验证选中的加密媒体 → 开始下载。校验器绝不会对未选中的配置档或语言轨道进行采样。最终选轨前、最终选轨后与自定义许可三种模式仍各司其职，职责不变。

直播播放始终跳过该步骤，包括直播转点播（live-to-VOD）回放模式。未加密轨道、仅列出轨道、保存导出文件以及仅生成下载命令本身都不会触发媒体验证。启用该功能后，生成的下载命令会自动附带 `--verify-keys` 参数，并在实际执行该命令时运行预检。独立下载器仅校验传入的密钥，无法代为重新向服务请求许可证，也不接触账号凭据。

## 采样验证的判定标准

校验器基于受限的 HTTP 字节范围请求拉取完整的分片 MP4（fragmented MP4）样本，而非随意截断的下载块。若存在 MP4 SIDX 索引，校验器可直接定位分布在不同位置的媒体分片，无需下载中间内容；若缺少合适索引，则退回受限的 box 头遍历。

未加密片头（clear lead）不算验证通过。内置 CENC/CBCS 解密器必须切实改写目标 KID 对应的真实媒体载荷，且解码窗口中的首个媒体样本必须受到解密影响。纯明文开头或无法安全判定的混合窗口会被跳过，改用其他样本。随后，FFmpeg 必须实际解出视频帧或音频采样。仅仅识别出容器头或解密进程退出码为 0 并不足以判定通过。

当前首批实现面向内置的分片 MP4 CENC/CBCS 路径；其他封装容器与传输层加密方式需要日后补充对应适配器。缺少解码器、遇到不支持的布局、样本不完整、媒体不可访问或采样预算耗尽，均判定为**无法确定（inconclusive）**，而不是坏密钥。遇到无法确定时，系统会发出警告并继续正常下载，同时不宣称验证通过。只有在两个加密样本均解码失败后，候选密钥才会被否决。验证通过属于提前预警手段，并不能证明后续每一个分片或轮换后的新 KID 都必然有效。

每个标题的采样上限为：拉取数据总量 32 MiB、请求次数 48 次、单次请求 8 MiB，以及总计 45 秒的采样与解码预算。每次解码同时设有 8 秒超时并限定使用单线程解码。密钥库与服务许可证请求各自保留原有超时设置。拉取到的密文样本会在不同候选密钥之间复用；探测期间获知的响应大小也会被后续的视频码率探测复用。预检结束后仅保留大小元数据，不会在批量队列的每一行上滞留媒体载荷。临时样本文件与正常下载文件及断点续传文件完全隔离。

## 候选顺序与失败处理

密钥库查询依然遵循“先本地，后按配置顺序查远程”，且只访问已启用的读取目标。针对每个选中的 KID：

1. 首先验证当前下载流程已经拿到的密钥。
2. 如果该密钥来自密钥库且验证失败，依次尝试其他已选中本地密钥库中的候选，再尝试已选中远程密钥库中的候选。本地数据库中有限数量的历史旧候选也会纳入尝试。
3. 自动跳过重复的相同候选，不会为了再次拿到同一个已否决的答案而重复查询用过的远程源。
4. 如果所有密钥库候选都验证失败，则使用当前已配置的授权上下文和设备，向服务/CDM 发起一次针对失败轨道清单的许可证请求。
5. 如果这次结果仍然失败，或返回了此前已否决的相同候选，则中止当前标题。直接从 CDM 刚获取的密钥，或由导出文件导入的密钥，都不会触发循环重试许可证。

密钥获取阶段本身不会运行任何媒体探测。校验器不会切换 DRM 系统、CDM 设备或播放配置档，也不会把可移植导出文件转变为已登录的服务会话。批量下载时的失败处理继续沿用现有的单标题失败策略。

## 密钥库写入安全

为某次下载开启验证后，密钥库命中的结果先视为待定（provisional）。远程查得的密钥只有在验证通过后才会回填到本地，且严格遵守本地写入目标与只读密钥库限制。刚从许可证获取的新密钥也只有在验证通过且现有写入策略允许时才会被写入。未参与验证的轨道密钥不会因为另一把密钥通过就顺带获判有效。

该功能不会引入密钥库之间的自动同步，也没有持久化的坏密钥黑名单、不会自动删除本地记录、不会删除远程记录，也不会上报坏密钥。失败的候选仅在本次预检期间被排除；判定为“无法确定”的候选既不会被标为坏密钥，也不会作为已验证密钥向外传播。
