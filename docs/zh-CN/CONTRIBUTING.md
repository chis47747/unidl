# 为 unidl 贡献代码

[English](../CONTRIBUTING.md) | [简体中文](CONTRIBUTING.md)

UniDL 的服务层负责账号、目录检索与密钥获取；原生交付核心属于同一应用的组成部分。请保持这一架构边界：服务可以处理登录、发现播放源和获取密钥；原生核心则全权负责 manifest 解析、轨道选择、下载、解密、字幕处理和混流。

## 修改代码前

1. 按 [testing.md](testing.md) 说明创建虚拟环境，并安装 UniDL 及开发依赖。
2. 阅读 [architecture.md](architecture.md)；如果涉及服务开发，还请阅读 [writing-a-service.md](writing-a-service.md)。
3. 不要将凭据、Cookie、令牌、设备文件、内容密钥、命令导出文件和调试日志提交到版本控制。项目支持在仓库内使用可见的本地运行时目录布局，但这些路径必须保持在忽略列表中。

## 项目规范

- 服务代码绝不能导入 Textual，也不能调用 `print()` 或 `input()`。所有交互均通过 yield Flow ask 完成，并最终返回 `Playback`。
- HTTP 客户端与响应解析放在服务的 `api.py` 中，交互流程放在 `__init__.py` 中。
- 每个提供方在 `src/unidl/services/` 下作为单独的原生包存在。随代码库内置的服务可使用单个 `@registry.register` 装饰器；用户自行导入的服务包可在 TUI 注册后依赖加载器的自动类注册。无论哪种方式，都不要在 `src/unidl/services/__init__.py` 中添加二次手动导入。具体要求见 [writing-a-service.md](writing-a-service.md)。面向终端用户分发服务包时，用户需将其复制到 `<paths.home>/services`（或当前生效的包/源码服务目录），打开 **设置 → 服务 → 注册服务**，然后重启 UniDL，该服务才会出现在主界面或全局搜索中。源码检出环境需通过 `uv sync` 或可编辑模式安装运行，或通过 `UNIDL_SERVICES` 指定服务根目录。
- 不要在服务中重复实现原生交付核心已有的 manifest 解析、选轨或下载逻辑。
- 不要硬编码凭据、本地绝对路径或外部工具路径。
- 显式声明服务设置、凭据、外部工具（Helper）与 `DRM_SYSTEMS`，不要让 UI 从服务内部实现自行推断。
- 共享的“轨道输出选择”仅控制原生交付核心最终下载和混流哪些轨道。绝不能将其画质/编码/动态范围/音频/字幕设置复用作许可证轨道策略；如需配置许可证轨道、档位或 PSSH 种子，必须在该服务自己的配置分区中定义独立设置。应用级的“选轨后许可证兼容模式”由核心层实现，并不意味着服务代码可以读取这些共享设置。
- 仅通过 `ctx.tokens` 读写会话状态，其根目录固定为 `paths.tokens` 下属于当前服务的子目录。传参时只写文件名，不要写目录名：`TokenStore` 会拒绝路径分隔符、绝对路径和 `..`。
- 重命名服务状态文件时应执行移动而非复制：保留旧文件名会导致退出登录时无法清理旧文件，并在下次读取时重新接管旧会话。
- 说明性文档中不要写死服务总数。迁移记录可以引用某次实测快照，其他文档均不应写死具体数量。

## 代码变更同步更新文档

请在同一次变更中更新对应的参考文档：

- 新增或调整配置键：`docs/configuration.md`，如适用，同步更新 `src/unidl/unidl.yaml` 中的无凭据默认项
- 全局或轨道设置：`docs/settings.md`
- Flow ask 或服务钩子：`docs/writing-a-service.md` 及参考服务注释
- 界面、快捷键或快照目标：`docs/interface.md` 与 `docs/ui-design.md`
- DRM 或密钥库行为：`docs/drm.md` 或 `docs/key-vault.md`
- 新增验证命令或测试夹具：`docs/testing.md`

新增面向用户的文档时，请在 `README.md` 中添加索引，并在仓库内使用相对 Markdown 链接。

## 验证

先运行 `ruff` 和 `compileall`，再运行最小范围的相关离线检查。仅在具备所需账号、地区、设备与授权前提下执行在线检查（live checks），并在说明中明确列出实际运行和未运行的命令。严禁在缺陷报告或代码评审中粘贴真实凭据、完整内容密钥、CDM 密钥材料或未脱敏的调试日志。

移植服务时，必须针对真实服务实际验证每一个声明的入口点。仅能成功导入模块，并不能证明登录、目录解析、许可证获取或当前第三方接口结构能够正常工作。

## 开发期间重新加载服务代码

unidl 不会自动监听源码变更。如需在不退出的情况下加载修改后的代码，请先开启全局 **调试模式**，回到无弹窗的主界面，高亮选中目标服务（或筛选至仅剩一个服务），然后按 `ctrl+r`。该操作会先编译所选服务已加载的源码，按依赖顺序重载其多文件包，并同步重载共享这些模块的原生服务包。核心层、TUI 及无关服务模块不在重载范围内。

注册表会更新为新的类定义，因此只有**下一次**进入服务会话时才会使用新代码。当前正在运行的服务实例、下载任务、许可证交换、心跳或播放会话清理流程不会被热修补。当屏幕上打开了服务界面或浮层时，重载功能默认不可用。

这是一项开发便利功能，并非事务性的生产热更新机制。语法错误会在改动任何模块前被拦截，导入出错后也会恢复旧注册表，但 Python 无法完全回滚已开始执行的导入对模块全局状态造成的修改。如果重载失败，或执行了新增/删除/重命名模块与符号（旧名称可能残留在模块命名空间中），请重启 unidl。修改服务 ID 后同样需要重启。

## 变更说明

提交变更时请说明：

- 哪些用户可见行为发生了变化；
- 促成本次改动的契约要求或缺陷；
- 运行了哪些检查及所处环境（离线、本地回环或在线）；
- 涉及的任何账号、地区、外部工具、CDM 或外部服务限制；
- 用户需要执行的迁移或配置步骤。

请仅在您拥有合法访问授权的账号和内容范围内使用本软件。
