# UI 设计规范

[English](../ui-design.md) | [简体中文](ui-design.md)

适用于 unidl 中每个页面的强制规范。如果某个页面违反了其中任意一条，错的是页面，而不是规范。

## 四个核心页面

从选择服务到完成交付的整个流程包含四个页面，每个页面只回答一个问题。

| # | 页面 | 回答的问题 | 实现类 |
|---|------|------------|--------|
| 1 | 首页（Home） | 选择哪个平台？ | `tui/home.py:HomeScreen` |
| 2 | 服务首页（Service home） | 要在这个平台上做什么？ | `tui/service_screen.py:ServiceScreen` |
| 3 | 流程页（Flow） | 执行服务的具体交互：选片名、选季、选轨 | `tui/flow_screen.py:FlowScreen` |
| 4 | 交付页（Delivery） | 执行下载，或输出命令 | `tui/download_screen.py:DownloadScreen` |

首页的平台列表可以通过 `ctrl+g`、`v` 或 `SERVICES … available` 标题最右侧的 `view` 控件循环切换。共有三种确定性视图：按字母顺序（A–Z）、按国家、按媒体类型。国家信息属于静态元数据，并非实时定位检测：服务的第一个 `GEOFENCE` 代码作为其主市场，未声明则归入“国际”（International）。媒体类型由服务声明为音频、视频或两者兼具；兼具两种类型的服务会归入独立的“音频 + 视频”（Audio + video）分组，避免只关注其中一类的用户看不到该平台。当筛选框为空时，最近打开过的服务会以紧凑的**最近使用（Recently used）**栏（最多 5 项）显示在网格上方。筛选、键盘导航和数字编号直达在所有视图中保持一致。状态栏仅用于呈现运行状态和快捷入口：CDM、DRM、选定后操作、就绪状态、导入和定时下载。

首页字符标题下方的两行说明同样是可点击控件：点击版权信息会打开内置的开源项目致谢；点击版本号会打开本地更新日志与版本状态。首页会在后台工作线程中查询公开的 PyPI JSON 接口和公开的 GitHub Releases 接口，采用短超时且不携带凭据。若发现新版本，版本号旁会显示向上的更新标记，弹窗中会提供 PyPI 与 GitHub 链接以及 GitHub 发布说明。检查失败或不完整时，界面绝不会宣称当前已是最新版，也绝不阻塞服务浏览。远程发布说明仅作为纯文本展示，不具备执行任何命令的权限。

页面 2 到页面 4 共用 `tui/askhost.py:AskHost`，它封装了除页头外的整套交互机制：一个当前挂载的提问控件、日志区，以及让工作线程阻塞等待用户回答的通信通道。这三个页面的区别仅在于内容区上方展示的信息。

某个提问落到哪个页面由提问对象自身的 `Ask.scope` 决定，取值为 `root`、`flow` 或 `delivery`。服务除顶层菜单外不会主动设置该字段；默认值将其放入页面 3。`tui/session.py:SessionController` 根据该作用域自动压栈或出栈。

设置和搜索属于叠加在当前页面之上的浮层（overlay），不属于上述四页序列。

### 返回始终只回退一个逻辑页面

返回操作只退回紧邻的上一页，而不是直接跳回服务首页。搜索结果、分季、分集和片源选择可以复用同一个 `FlowScreen`，但仍须逐级回退。无论成功、失败、已保存命令还是导出结果，返回目标都保持一致；浮层关闭时只关闭自身。服务已自行实现的返回导航，不得再由 Core 包装层额外叠加一次返回跳转。完整的流程、批量与错误处理约定见 [navigation.md](navigation.md)。

### 从已保存的结果返回

已保存的下载命令、导出文件以及仅列轨道的结果会停留在流程页，直到用户阅读完毕。按下返回（包括点击顶栏返回控件）或 Enter 会关闭结果视图，并让服务恢复到先前的输入提示或片名选择器。如果下一个问题是服务顶层菜单，控制器会关闭流程页并挂载该菜单。关闭结果页时，不得与恢复提示的挂载产生并发出栈、不得取消服务工作线程，也不得重放已经完成的下载或导出操作。批量结果同样保留至用户主动关闭。

### 页面彼此替换，绝不累积状态

从一个页面进入下一个页面时，**会清空上一页的界面状态**。每个页面都是独立的 Textual `Screen`，通过压栈和出栈切换，因此页面 2 的状态不会泄漏到页面 3；从页面 3 返回页面 2 时也会丢弃页面 3 的展示内容。

由此得出一条约束：页面绝不能作为下一页面所需状态的唯一持有者。任何需要跨页保留的状态都必须存放在会话控制器（`tui/session.py:SessionController`）中，而不是控件实例里。

## 通用页面框架

每个页面都按相同顺序由以下区域组成：

```
┌──────────────────────────────────────────────────────────────┐
│ CHROME      左侧：导航               右侧：搜索、设置        │  1 行
├──────────────────────────────────────────────────────────────┤
│ IDENTITY    当前身份与位置，以及状态和参数                   │  高度可变
├──────────────────────────────────────────────────────────────┤
│ CONTENT     当前页面唯一要处理的核心内容                     │  1fr
├──────────────────────────────────────────────────────────────┤
│ LOG         刚刚发生的操作                （页面 2、3、4）   │  8 行
├──────────────────────────────────────────────────────────────┤
│ KEYBAR      当前上下文的快捷键                               │  1 行
└──────────────────────────────────────────────────────────────┘
```

### 顶栏（Chrome）

各控件位置固定，便于形成肌肉记忆。搜索和设置永不移位。除首页外，所有页面均提供“返回”；首页处于页面栈最底层，没有上一级，放置一个不可点击的灰显按钮反而比不显示更糟。

| 页面 | 左侧 | 右侧 |
|------|------|------|
| 1 首页 | 退出 | 搜索 · 设置 |
| 2 服务首页 | 返回 · 退出 | 搜索 · 设置 |
| 3 流程页 | 返回 · 退出 | 搜索 · 设置 |
| 4 交付页 | 返回（停止整个队列） · 暂停/继续交付 · 退出 | 搜索 · 设置 |

每一项同时支持鼠标点击和快捷键触发。顶栏条目以**面板背景色加粗文本、左右各留两列内边距**渲染，使其在视觉上明确呈现为控件而非普通文字。

> 终端只有一种字体和一种字号，由终端模拟器决定而非应用程序。“更大”的层级只能通过字重、对比度、间距和背景色表达，主标题则通过不同高度的块状字符画呈现。

快捷键：

| 操作 | 组合键 | 备选键 |
|------|--------|--------|
| 返回 | `ctrl+b` | `b` |
| 退出 | `esc`（按两次） | `ctrl+q` |
| 搜索 | `ctrl+f` | `/` |
| 设置 | `ctrl+s` | `s` |

界面主推控制组合键，因为即便输入框处于焦点状态它们也依然生效；单字母快捷键在输入文本时会自动让位于打字。`ctrl+k` 不可使用，因为 Textual 的 `Input` 将其绑定为“删除至行尾”。

### 浮层同样携带完整框架

设置、搜索、设备选择器和值编辑器与其他页面一样都是标准 `Screen`，因此同样绘制相同的顶栏和底部快捷键栏。若某个页面省略了它们，“返回”和“退出”就会从固定角落消失；快捷键虽然仍可用，但看不见的控件就称不上控件。

半透明弹窗无法满足这一点，因为底层页面自身的顶栏和快捷键栏会透出来，用户无法一眼分辨哪一层才是当前激活的控件。因此值编辑器采用不透明背景，卡片居中，外围框架维持原位。

### 身份栏（Identity）

视觉层级有意设计为单调递减：进入层级越深，标题越小。

| 页面 | 标题样式 | 高度 |
|------|----------|------|
| 1 首页 | 大号块状字符 `unidl`，居中 | 6 行 |
| 2 服务首页 | 小号块状字符服务名，居中；非拉丁文字使用系统 UI 字体渲染为同风格 `▀▄█` 半块马赛克 | 拉丁文字 3 行，CJK 及其他文字 6 行（终端过窄时降为 1 行） |
| 3 流程页 | 加粗文本服务名 | 1 行 |
| 4 交付页 | 加粗文本服务名 | 1 行 |

标题下方是一行状态与参数栏。页面 1 展示 CDM、DRM 系统、选定后操作、就绪状态、导入和定时下载；页面 2 到 4 展示已登录账号、CDM 以及当前生效的轨道偏好。

服务名属于业务数据，而非界面文案。它们保留原始 Unicode 形式，并通过双向文本（BiDi）安全边界渲染；CJK 与宽字符按真实终端单元格宽度计算，手绘拉丁字形表未覆盖的文字会栅格化为 6 行高的半块马赛克真实字形。仅当没有任何字体可栅格化该名称时，才退回带边框的文本块。界面本地化仅翻译 UniDL 自身的标签和提示，绝不翻译服务名、片名数据、URL、文件名、KID 或 API 语言设置。详见 [i18n.md](i18n.md)。

### 日志栏（Log）

页面 2、3、4 带有日志栏。它在有内容写入前保持折叠状态，可按 `ctrl+l` 展开，也是强制报告的输出位置。

页面 1 不包含日志栏，因为它不执行实际业务操作。

## 强制报告

每当一条播放信息解析完成——无论来自哪个服务、哪个入口、点播还是直播、处于哪种模式——都必须按以下固定顺序和语义配色输出报告：

| 字段 | 配色 | 说明 |
|------|------|------|
| `title` | 强调紫（accent violet） | 人类可读标题 |
| `save as` | 主文本色 | 输出文件名 |
| `manifest` | 蓝色 | 移交给原生交付核心的 URL |
| `kind` | 黄色 | 仅直播时显示 |
| `note` | 弱化色（muted） | 仅在服务有附加说明时显示 |
| `key` | 绿色 | 每条 `kid:key` 占一行，或显示“无需密钥（none needed）” |

报告必须以 Rich `Text` 对象而非标记字符串（markup）写入，防止标题或 URL 中的方括号被误解析为样式标签。日志内容支持鼠标拖选并自动复制。

### 交付详情与控制

交付页在日志中保留强制报告的同时，会在进度区域上方增加一个紧凑、可滚动的详情区，列出输出路径、解析来源、选择摘要、每一条已选轨道、每条加密轨道对应的 KID，以及移交给原生交付层的全部 `KID:KEY`。这里仅作核查信息展示，并非二次选轨器，不会修改最终选择。

当服务提供了章节信息时，同一区块会显示章节总数与时间跨度；较短的章节列表会直接展开，较长列表则通过 `Chapters` 按钮（或按 `c`）打开专用的可滚动章节视图。章节标题同样属于服务数据，Unicode 与 RTL 标题经过与其余元数据相同的安全渲染边界处理。

界面上可见的**停止（Stop）**控件与离开交付页发送同一个原生取消令牌。取消排空期间按钮变为禁用态的**正在停止（Stopping）**；若已取消的任务保留了可续传的原生分段，该控件会切换为**继续（Resume）**。返回操作会停止整个队列，而已有的跳过操作仅停止当前行。退出操作首次按下时仅发起取消，第二次按下才是显式退出应用。

进度卡片直接消费 Core 发射的结构化事件，不会劫持终端标准输出，也不会把屏幕控制权交给独立 CLI。

传输完成标注为**已下载（Downloaded）**，而非整个任务完成。后处理行会把当前阶段名称放在文件名前面，避免过长的临时路径遮挡解密或转码状态。音频转换会报告 FFmpeg 已处理的媒体时长、相对播放速率，以及在已知音轨总时长时显示进度百分比和预计剩余时间；时长未知时则省略百分比与预估，绝不凭空编造。只有 FFmpeg 正常退出才算转换完成；处理到媒体末尾后仍会留出写入标签、封面、章节和输出尾部信息的时间。

纯音频交付是唯一有意设计的交付页布局变体。选轨阶段，左侧预览栏显示专辑封面和 ID3 元数据，右侧用于轨道选择；开始下载后，左侧切换为下载进度和混流状态，封面与元数据预览则保留在右侧。视频点播与直播录制不会生成该侧栏，继续使用上述全宽布局。

当终端宽度小于 112 列时，交付页封面侧栏会自动隐藏，将全部宽度让给实时进度；窗口拉宽后会重新显示，选轨状态与已缓存的封面不受影响。

### 轨道行配色

轨道行保持默认前景色，复选框负责表达选中状态。仅特殊规格徽章（Dolby Vision、HDR10/HDR10+、HLG、HDR Vivid、Atmos 和 Audio Vivid）使用各自的语义配色。

音频和字幕轨道上的 `Original` 字样使用独立的 `original` 语义角色：一种克制的灰青色，在深色表面略亮、在浅色表面略深。即便它紧跟在其他角色之后（如 `Dialog Original` 或 `Forced Original`），也只高亮 `Original` 这个词。轨道选择器与下载轨道详情共用同一语义角色。轨道标识符中包含的 `_original_` 不属于徽章，样式也绝不会影响轨道是否被判定为原声/原始语言。

## 交互规范

### 三种等价的选择方式

鼠标点击、输入名称、输入编号三者完全等价。每个列表都带编号，且同一页面内的编号连续，确保任意数字指向唯一条目。

首页还包含一个仅在开发阶段生效的操作：开启全局调试模式（Debug）后，按 `ctrl+r` 会重新加载当前高亮的服务、输入的精确 ID/编号，或筛选后唯一剩下的服务。这是一个手动触发的安全重载点，绝非后台文件监听。重载后首页会使用新的注册表类重建网格单元；进入服务后的任何页面都不暴露该操作，因此运行中的服务实例及其播放生命周期不受影响。

### 凡是显示状态值的项都可直接修改

首页状态行上的每一项都是可交互控件，而非静态标签：

| 状态项 | 点击后的行为 |
|--------|--------------|
| `cdm <name>` | 打开 CDM 设备选择器 |
| `drm <system>` | 循环切换已注册的 DRM 系统 |
| `after picking <action>` | 循环切换下载 / 仅保存命令 / 仅列轨道 / 导出 / 每次询问 |
| `ready` / 状态 | 打开就绪检查与诊断报告 |
| `import [count]` | 打开导出导入队列 |
| `schedule [summary]` | 打开定时下载与即将上映雷达管理器 |

每一项都是独立控件而非富文本标记片段，因为只有独立控件支持 `:hover` 样式。悬停高亮本身就是可点击的交互提示。

切换 DRM 系统时会同步切换配套设备：沿用其他系统的设备会导致静默错误，因此会自动选中首个匹配的设备，或明确提示所需目录和文件后缀。反向选择设备也是同理：`.wvd`、`.prd` 和 `.mld` 分别对应 Widevine、PlayReady 和 MonaLisa。

### 输入框固定在底部

用户键入的内容统一出现在页面底部。输入框正上方有一行灰色提示，用完整词语而非缩写说明该输入框接受什么内容。

### 选择快捷键

| 按键 | 操作 |
|------|------|
| `↑ ↓ ← →` | 移动光标，在网格中支持二维方向移动 |
| `enter` | 选中当前高亮项；若多选中已有勾选项，则确认已勾选批次 |
| `space` | 在多选列表中切换勾选状态 |
| `a` / `n` | 全选 / 清空当前可见列表 |
| 数字键 | 直接跳转到对应编号 |
| `home` / `end` | 跳到首项 / 末项 |
| `ctrl+r` | 仅首页可用：在调试模式开启时显式重载所选服务代码 |

当多选列表打开时已由自动规则预先勾选了选项，按 `enter` 会直接采纳；如果当前没有任何勾选项，按 `enter` 会像单选列表一样选中当前高亮行，从而让“搜索 → 选季 → 选集”的常规操作路径保持一致。需要批量选择时，先用 `space` 逐一勾选，再按 `enter` 确认所有勾选项。

### 长列表支持随输入实时筛选

任何达到或超过 10 条的列表都会在底部附带筛选输入框（`tui/filterbox.py`），所有页面遵循与平台列表完全一致的交互契约：

- 输入字母可缩小列表范围，以空白分隔的每个词都必须命中条目的标签、详情或标签字段中的某处；
- 输入数字用于按编号寻址，因此键入数字会清空当前筛选并直接指向对应编号；
- 焦点停留在输入框时，`↑ ↓` 和 `page up` / `page down` 仍可移动列表高亮项。

开启筛选期间，条目编号保持原值不变。如果编号会随筛选结果变动，它就失去了“地址”的意义，这也是键入数字会清空筛选而非把它当搜索词的原因。

不同类型列表的初始焦点位置有意区分：

| 列表类型 | 初始焦点 | 原因 |
|----------|----------|------|
| 单选列表 | 筛选输入框 | 核心任务是快速查找并选中，按 `enter` 即打开高亮项 |
| 多选列表 | 列表本身 | 核心任务是勾选多项，`space` 必须用于切换勾选而非输入空格 |

在多选列表中，筛选只改变可见视图，不会取消勾选。已勾选项独立于当前可见行保存，因此你可以先筛选 `S01` 勾选两集，再清空筛选，之前的勾选依然保留。提示行会标明已选数量，并在其中包含被筛选隐藏的条目时给出明确提示。

### 鼠标与剪贴板

点击任何可操作元素即可触发。按住鼠标左键拖选文本，松开后通过共享剪贴板边界自动复制。Windows 平台直接写入原生 Unicode 文本（含非拉丁字符和 emoji），无需依赖 PowerShell 或支持 OSC 52 的终端；若剪贴板暂时被其他进程占用，会持续重试约 80 ms。macOS 使用 `pbcopy`；Linux 按可用性依次尝试 `wl-copy`、`xclip` 和 `xsel`。

鼠标拖选、命令、导出路径、密钥、链接和日志复制共用同一套结果处理逻辑。只有系统原生剪贴板写入成功才会弹出“已复制”提示；写入失败既不会误报成功，也不会导致 TUI 崩溃。OSC 52 和应用本地缓存作为回退手段保留。仅通过终端转义序列尝试复制时，会明确提示状态未确认，因为发送转义序列并不代表终端一定接收了它。若仍无法粘贴，请直接选中终端可见文本并使用终端自身的复制命令。内部代码调用 `app.copy_text(text)` 时，如果返回 `False` 应停止发送成功提示——应用层已自动展示本地化的警告通知。

### 破坏性操作需要二次确认

退出应用需要在 1.5 秒内再按一次 `esc`，防止误触快捷键中断正在进行的下载会话。

## 作用域划分

“搜索”和“设置”的含义随所在页面变化，这是让每个页面专注回答一个问题的关键设计。

| | 页面 1（首页） | 页面 2 到 4（服务内） |
|---|----------------|------------------------|
| 搜索 | 搜索服务、片名以及整个密钥库 | 仅搜索当前服务的密钥 |
| 设置 | 7 个精简的全局管理页：下载行为、服务、DRM 与密钥库、文件与命名、代理与 VPN、JustWatch 搜索、界面与诊断 | 当前服务专属选项、授权与密钥库策略、轨道偏好 |

服务设置仅对当前服务生效。

设置项的“标签 / 值”列表统一使用 `tui/settings_layout.py`：按真实终端单元格宽度测量翻译后的标签，整张列表共享同一列的值起始位置，并在空间不足时让标签和值各自独立换行。计算换行前必须先预留垂直滚动条宽度；窗口缩放后自动重新排版，同时保持当前高亮设置项不变。每一行都是宽度感知的 Textual 视觉对象：在渲染阶段执行换行，而不在列表宽度仍为 0 的挂载阶段处理。不要依靠刷新后重建来修补错乱的首帧，也不要仅为重排折行而重建非活动设置页面。切勿逐行独立补齐空格，也切勿用字符个数替代 CJK 文本宽度。管理页的帮助面板在窗口内自动折行，即使在较矮的窗口中也始终保留与页头一致的三列水平缩进，仅压缩垂直间距。

## 命名约定

平台名称必须显示为品牌名，而非内部文件名：显示 `BBC iPlayer`，而不是 `bbc`。界面统一基于一套原生服务注册表与一套交付契约运作，使各平台的导航和错误处理保持一致。

界面文案中统一称“配置（config）”，不要称“yaml”。用直白的语言写清设置的作用：例如写“选定之后立即下载文件（after picking download the file）”，而不是生硬的缩写“on pick download”。

## 响应式布局

平台网格根据真实终端宽度动态重算列数：实测 118 列宽显示 5 列，64 列宽显示 2 列。底部快捷键栏从右侧整项省略提示，绝不在词语中间截断；行详情信息同样整段省略而非生硬裁剪。

## 双向文本（BiDi）标题

服务层与核心层中的字符串始终保持 Unicode 逻辑顺序。搜索、筛选、缓存键、显式复制动作和输出文件名绝不能接收经过视觉翻转的标题。在 TUI 渲染边界，由 `tui/bidi.py` 生成仅供终端显示的副本：使用 Unicode BiDi 算法排布希伯来文和阿拉伯文片段，在不丢失元音变音符号的前提下完成阿拉伯文连字塑形，并对远程标题中携带的 Textual 标记与显式 BiDi 覆写/隔离控制字符做无害化处理。中文和欧洲从左到右文字则原样通过。

该转换只在公共选择器、表格和页头渲染器中统一调用，不要分散写在单个服务内部。界面测试套件需要覆盖希伯来文/阿拉伯文、拉丁文、数字、组合附加符号和 CJK 混排的场景。

## 配色与外观

UniDL 内置七套基于语义角色令牌的主题：**Dark**（深色，默认）、**Light**（浅色）、**Tokyo Night**、**Catppuccin Mocha**、**Nord**、**Gruvbox** 和 **High Contrast**（高对比度）。默认选择 Dark 是因为它在 256 色终端上也能平滑量化；Light 和 High Contrast 无需自定义样式表即可满足明亮终端与无障碍对比度需求。

在基础主题之上，**设置 → 界面与诊断**提供四项彼此正交的外观控制，且全部支持**实时预览**（移动高亮项即刻重绘界面；按 `Enter` 或点击**应用**保存，按 `Esc` 恢复原值）：

- **系统配色**（`accent_color`）：9 种预设（`violet`、`colorful`、`blue`、`cyan`、`green`、`amber`、`orange`、`rose`、`mono`）。
- **标题颜色**（`title_color`）：跟随系统配色，或 12 种渐变/纯色横幅预设（`rainbow`、`aurora`、`sunset`、`ocean` 及多款纯色）。
- **界面密度**（`layout_density`）：`auto`（随终端高度自适应）、`comfortable`（舒展）或 `compact`（紧凑）。
- **状态语义色**（`semantic_colors`）：`default`（默认）或 `colorblind`（色盲友好，采用高区分度的 Okabe–Ito 正常 / 警告 / 错误配色）。

所有颜色均按**语义角色**而非色相命名，使每套主题都能针对自身背景选用合适的对比度（例如 `ok` 在 Dark 下是亮绿色，在 Light 下是更深的森林绿）。Dark 与 Light 基准令牌如下：

### 如何引用颜色

严禁硬编码十六进制色值。无论在样式表还是控件标记中，颜色都必须引用 Textual 设计令牌——`$accent`、`$muted`、`$gutter`、`$manifest`、`$ok`、`$warn`、`$bad`——这样切换主题时即可全局即时重绘，无需重启。

唯一例外是写入日志区的 Rich `Text`：Rich 自行解析样式，不感知 Textual 令牌。这些调用点应按角色名从 `app.palette` 读取当前主题的实时色值，确保同样跟随主题变化。

切换方式：`ctrl+t`、命令面板或设置页，选择会被持久化记住。

布局间距遵循统一约定：上下 1 行内边距，左右 2 列内边距；不使用嵌套方框；除日志区上方的一条分隔线外不加额外边框。

未勾选复选框与已勾选复选框使用同一字形，未勾选时以 `panel` 背景色绘制。选中状态完全靠颜色区分，这也是两套基准配色都在 `accent` 与 `panel` 之间保留充足对比度的原因。

## 页面验证

使用以下命令运行界面测试检查：

```bash
python -m pytest -q
```

以下是测试曾捕获过的两个典型布局陷阱，值得留意：

- Textual 控件的 `height` 包含内边距。设置 `height: 1` 同时加上 `padding-bottom: 1` 会导致内容区高度为 0，文本完全不可见而非被裁剪。
- 设置了 `border: none` 且内容为空的 `Input` 在视觉上与空白背景完全无法区分。因此所有提问输入框都在左边缘绘制一条强调色竖条，让光标位置清晰可见。
