# Interface language and localization

[English](i18n.md) | [简体中文](zh-CN/i18n.md)

UniDL's interface language is an app-wide setting, completely independent of
service API locales and audio/subtitle track languages. Service catalogues and
media metadata stay Unicode-safe and untranslated, and the title banner renders
CJK and RTL service names directly without translating them.

## Supported locales

UniDL ships 12 built-in catalogues under `src/unidl/locales/*.json`:

| Code | Language | Notes |
|------|----------|-------|
| `en` | English | Source and fallback catalogue (American English). |
| `zh-Hans` | Simplified Chinese | 简体中文 |
| `zh-Hant` | Traditional Chinese | 繁體中文 |
| `es` | Spanish | Español |
| `fr` | French | Français |
| `pt` | Portuguese | Português |
| `it` | Italian | Italiano |
| `ja` | Japanese | 日本語 |
| `ko` | Korean | 한국어 |
| `ru` | Russian | Русский |
| `de` | German | Listed as **Deutsch**; `de-DE`, `de-AT`, `de-CH`, `de-LI` and `de-LU` map here. |
| `ar` | Arabic | العربية — pure logical Unicode order in JSON; rendered right-to-left with mirrored layout rules. |

Change the language under **Settings → Interface & diagnostics → Interface
language**. The default `system` choice checks `LC_ALL`, then `LC_MESSAGES`,
then `LANG`, falling back to `en`. Switching languages repaints active screens
and overlays in place without restarting a session or invalidating sign-in
state.

## Translation boundary

Only UniDL-owned interface copy is translated:

- chrome and key-bar labels (`Back`, `Quit`, `Search`, `Settings`);
- picker headings, hints, validation messages, and delivery statuses;
- global setting labels/help and manager screens (Download behavior, Services,
  DRM & vaults, Files & naming, Proxy & VPN, JustWatch, Scheduled downloads,
  Interface & diagnostics);
- command palette entries, shortcuts reference, search/vault dialogs, and
  native-downloader progress/status text;
- diagnostics and notifications generated by UniDL itself.

The following values always stay untouched in logical Unicode order:

- service names, title names, episode names, and account labels;
- URLs, file paths, filenames, KIDs, keys, codecs, and DRM identifiers;
- service-owned API errors and metadata unless a service explicitly provides a
  display label;
- user input and anything written into commands, exports, or key vaults.

Interface language never alters a service's API `locale` or track-language
selection.

## How it works

UniDL uses its own package-local message catalogue in `src/unidl/core/i18n.py`
rather than Python's process-wide `gettext` locale, so multiple sessions never
mutate a service client's or shell's locale:

- `supported_locales()` exposes the 12 stable locale codes.
- `detect_locale()` resolves `system` from `LC_ALL`, `LC_MESSAGES`, and `LANG`.
- `tr(message_id, **values)` looks up descriptive dotted keys (`chrome.back`,
  `schedule.tab.jobs`) with named placeholders and falls back to `en.json` if a
  key is ever missing.
- Every catalogue is static package data loaded from `src/unidl/locales/*.json`
  and is never fetched over the network.
- Source strings remain in logical Unicode order (including `ar.json`, which
  must not contain Arabic Presentation Forms `U+FB50–U+FDFF` /
  `U+FE70–U+FEFF`). At the TUI render boundary, `tui/bidi.py` applies BiDi
  ordering, Arabic glyph shaping, and Rich markup escaping once. Layout and
  truncation measure real terminal cell widths rather than `len()`.

## Adding or updating translations

Every locale file must keep exact key parity with `en.json`:

- all 12 files parse cleanly as UTF-8 JSON and share the exact same key set;
- placeholder names (`{count}`, `{name}`, etc.) match `en.json`;
- translated labels containing square brackets escape cleanly in Rich markup;
- CJK and RTL layouts fit cleanly down to `80×24` terminals;
- changing `interface_locale` leaves service API requests, filenames, exports,
  and vault rows byte-for-byte identical.
