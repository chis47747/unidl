# Interface language and localisation

UniDL's interface language is an app-wide setting, independent of service API
locales and of audio/subtitle track languages.  The service catalogue and media
metadata stay Unicode-safe and untranslated.  The title banner can display CJK
and RTL service names without translating them.

The shipped catalogues are English, Simplified Chinese (`zh-Hans`), Traditional
Chinese (`zh-Hant`), Spanish (`es`), French (`fr`) and Portuguese (`pt`). Change the language from **Settings →
Interface & diagnostics → Interface language**. `system` follows `LC_ALL`, then
`LC_MESSAGES`, then `LANG`.

## What should be translated

Only text owned by UniDL's interface belongs in the first localisation pass:

- chrome and key-bar labels (`Back`, `Quit`, `Search`, `Settings`);
- picker headings, hints, validation errors and common delivery statuses;
- global setting labels/help and manager actions (DRM & vaults, Files & naming,
  Proxy & VPN, JustWatch, CDM picker/rules, Download behavior);
- search, add-keys, vault pickers, input placeholders and native-downloader
  progress/status text;
- diagnostics and notifications that UniDL constructs itself.

These values must stay exactly as supplied, in logical Unicode order:

- service names, title names, episode names and account labels;
- URLs, file paths, filenames, KIDs, keys, codecs and DRM identifiers;
- service-owned API errors and metadata unless a service explicitly supplies a
  translated display label;
- user input and anything written into a command, export or vault record.

In particular, the interface language must not become an API `locale` or track
language preference.  Those are independent service/output settings.

## Proposed implementation

Use a small, package-local message catalogue rather than Python's process-wide
`gettext` locale.  UniDL can run several sessions in one process and must not
change the locale used by a service client or by a user's shell.

1. Add `src/unidl/core/i18n.py` with:

   - `supported_locales()` returning stable BCP-47-ish IDs (`en`, `zh-Hans`,
     `zh-Hant`, `es`, `fr`, `pt`, `ja`, `ko`, `de` and later `ar`);
   - `detect_locale()` reading `LC_ALL`, `LC_MESSAGES`, then `LANG`, with an
     English fallback;
   - `Translator(locale, debug=False)` and `tr(message_id, **values)`;
   - an English source catalogue that is complete, so a missing translation
     never leaves an empty label;
   - optional debug reporting for missing IDs, without logging title data or
     credentials.

2. Store one app-wide `interface_locale` setting with `system` as the default.
   `system` is resolved once at startup; an explicit language is persisted in
   `settings.json`.  Changing it should rebuild the current screen and all
   overlays, not restart a service session or invalidate login state.

3. Keep message IDs stable and descriptive (`chrome.back`,
   `delivery.license_request`) instead of using English sentences as dictionary
   keys.  Use named placeholders and a small plural helper; never concatenate a
   translated noun into a sentence in a service module.

4. Translate at render boundaries.  Source values remain logical Unicode; the
   existing `visual_markup()`/`visual_text()` path is applied after translation,
   so Arabic/Hebrew ordering and Rich escaping are handled once.  Width checks
   use terminal cell width, not Python `len()`.

5. Migrate in layers: common chrome/key bar, settings and editors, asks and
   delivery statuses, then individual managers.  Service declarations can opt
   into message IDs later; their API/client code should not import the UI
   translator.

A catalogue can be a UTF-8 JSON file or a Python mapping.  JSON keeps translator
contributions independent from code, for example:

```json
{
  "chrome.back": "返回",
  "chrome.quit": "退出",
  "delivery.keys_cached": "已缓存 {count}/{total} 个密钥"
}
```

The English catalogue remains the fallback for missing or malformed entries.
Catalogues are static package data; they are never fetched from a service or
remote vault.

## Rollout and acceptance checks

The first implementation should ship with English unchanged, then add a small
Chinese catalogue for the chrome/settings path.  Before exposing more locales:

- every locale parses and has no unknown placeholder names;
- missing IDs fall back to English and are visible only in debug diagnostics;
- Rich markup parses for translated labels containing brackets;
- CJK/RTL snapshots fit at 80 columns and the title/banner keeps its three-row
  fallback;
- switching language while an overlay is open refreshes that overlay and the
  screen beneath it;
- service API requests, saved filenames, exports and vault rows are byte-for-byte
  unchanged by the interface-language setting.

This staged boundary avoids a half-translated screen and leaves service ports
free to retain their own API locale choices.
